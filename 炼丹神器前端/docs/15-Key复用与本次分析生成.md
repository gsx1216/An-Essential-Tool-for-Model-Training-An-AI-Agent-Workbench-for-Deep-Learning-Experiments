# Key 复用与本次分析生成

更新日期：2026-10-30。

## Key 只需保存一次

当前实现中，同一账号的聊天、报告分析、有据建议都使用这个账号已经保存的 DeepSeek Key，不需要为每个 Agent 分别配置。

```text
设置页保存 Key 一次
    ↓
后端校验并加密，按当前用户保存到 MySQL
    ↓
聊天 / 分析 / 建议需要调用模型
    ↓
UserModelGatewayFactory.create_for_user(user_id)
    ↓
读取该用户的密文 → 解密 → 创建本次网关 → 使用后关闭
```

“保存一次”指凭据已经持久化，不是把明文 Key 永久放入共享 Python 对象。读取、解密以及新建 SDK 客户端不会要求用户重新填写。

本次复用的是当前账号原先保存的 Key。服务器并未配置另一把全站公共 Key，没有复制个人 Key 供其他用户使用，也没有把 Key 写入前端、文档或新环境变量。

原有相关模块：

| 文件 | 作用 |
| --- | --- |
| `app/api/model_credential_routes.py` | 设置页保存、查询配置状态、删除本人凭据的接口 |
| `app/services/model_credential_service.py` | 校验、加密保存和内部解密读取 |
| `app/repositories/model_credential_repository.py` | 按用户持久化加密凭据 |
| `app/services/user_model_gateway_factory.py` | 为当前用户组装模型网关，供不同 Agent 复用同一份凭据 |
| `app/services/model_gateway.py` | 统一模型 API 和客户端关闭逻辑 |

以上凭据模块本轮没有修改；已通过真实调用确认既有复用机制生效。

## 本轮修复

真实执行中出现了两个问题：分析 JSON 不符合后端结构要求；建议流程中模型把工具协议输出成正文。失败任务和尝试次数均保留，没有删除失败记录来伪装成功。

### 分析输出

- 将 Pydantic 的完整 `ModelAnalysis` JSON Schema 放入提示词，明确字段、数组数量、字符串长度及禁止额外字段。
- 只有已识别的字段结构错误才允许纠正一次；再次失败仍不保存分析。
- 纠正前重新检查输入预算与租约，不重放工具或放宽证据路径校验。
- 无效 JSON、来源不符、伪造引用、存储失败等不会靠无限重试掩盖。

### 建议输出

- 工具正文格式异常最多纠正一次，保持本任务原有工具额度，不重新执行已经完成的查询。
- `ToolTextProtocolError` 归类为 INVALID_MODEL_OUTPUT，便于区别内部程序异常。
- 工具额度或上下文用尽时，缺乏源码/论文正文的组合证据就直接保存“证据不足”，不再调用模型伪造结果。
- 已取得完整证据时，结束阶段使用不带工具的 JSON 输出模式。
- 提示词提供建议结果 Schema，并要求合理分配源码与资料读取额度；不为某个项目写死专用建议。

### 本机日志

新增明确的模型输出字段校验事件，记录字段路径与错误类别，例如 `inferences:too_long`。日志不记录模型原文、错误输入值或 Key。建议开始、保存、需要处理的事件使用独立中文标签。

最早两次分析失败的原始模型正文没有持久保存，不能事后断言是某一个具体字段超限。本次改进保留结构约束，并让后续类似失败能准确显示校验位置。

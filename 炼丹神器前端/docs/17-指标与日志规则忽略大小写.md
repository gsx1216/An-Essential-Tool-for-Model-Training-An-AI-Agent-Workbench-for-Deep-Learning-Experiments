# 指标与日志规则忽略大小写

完成日期：2026-10-30。

## 使用方式

- 方案标识、数据集 ID、指标名与主指标接受大小写混写，保存时统一小写。例如 COD-Evaluation、Tiny_COD、MAE 分别保存为 cod-evaluation、tiny_cod、mae。
- 显示名称、版本说明、项目路径和日志原文保留原样；本次不修改训练参数名、文件名或密码的大小写规则。
- 正则的文字匹配默认忽略大小写。命名组 `(?P<MAE>...)` 可以对应页面的“平均绝对误差”（内部名 mae），`EPOCH`、`STEP` 同样可识别。
- 正则表达式保持原样，绝不把整个表达式转为小写，因此 `\D`、`\S` 等原有语法不会被改写。局部显式关闭忽略大小写的正则选项仍遵循 Python 正则语义。
- 结构化 JSONL 日志的指标键、元数据键、metric 类型、数据集 ID 和 train/validation/test 分组也忽略大小写。指标查询筛选支持相同规则。

大小写不同不再报错，但不同名称仍不是同一个指标：loss 和 mae 含义不同，不能互换。匹配模板仍须对应真实日志格式，`step=1 loss=0.5` 的模板不会匹配 `Epoch: 37 MAE: 0.017`。

例如实际日志：

```text
Epoch: 37 MAE: 0.01730551222264693 #### bestMAE: 0.017111
```

可以使用：

```text
^Epoch:\s*(?P<EPOCH>\d+)\s+MAE:\s*(?P<MAE>[-+0-9.eE]+)
```

选择“平均绝对误差”，分组按实际用途选“验证集”，数据集填实际 ID。保存并补采前先核对实际日志。

## 数据与兼容行为

不增加依赖、数据库表或迁移，不批量改写已有实验、日志、游标和报告，也不修改服务器项目文件。原有小写配置继续有效，已有冻结快照不批量重算。

同一条规则中 MAE 和 mae、同一份评测中重复的大小写变体、同一条 JSONL 记录中的 MAE/mae 双键，仍视为重复并拒绝，避免用一个数值覆盖另一个。原有数值范围、非法表达式、缺失轮次/步数、归属检查继续生效。

零有效指标的运行可以重新保存解析规则，从日志开头补采；已存在有效指标的运行仍遵循原有规则冻结约束，本次不清除历史数据或重启训练。

## 接口

- 创建实验使用原有 POST /experiments；evaluation 中的 protocol_id、datasets[].id、metrics[].name、primary_metric 忽略大小写。
- PUT /runs/{run_id}/metrics/parser：rules[].metrics、dataset、split 忽略大小写，pattern 内容保留。
- GET /runs/{run_id}/metrics：metric_name、dataset、split 查询参数忽略大小写。
- 所有接口继续使用现有 Bearer 登录和用户归属校验。

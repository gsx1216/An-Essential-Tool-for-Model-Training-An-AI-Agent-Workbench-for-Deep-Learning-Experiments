# 实验与运行永久删除

更新日期：2026-10-30。

## 页面入口与实际效果

“实验与训练 → 实验与运行”现在有两个独立入口：

- 实验信息卡片右上方的“删除实验”：永久删除本人实验、全部运行和所属训练配置及关联数据。
- 每条运行卡片里的“删除运行”：永久删除这条运行及其指标、报告、分析、建议等关联数据，保留实验定义、其他运行和训练配置。

两种操作都使用真正的数据库 DELETE，不写 deleted_at，也不只是隐藏前端卡片。已有“删除训练配置”按钮仍采用之前保留历史运行的语义；本模块没有改变那个独立功能。

确认框会展示对象和删除范围，点击确认才会发送请求。取消不删除；失败时保留卡片并显示原因。运行中或排队中的训练不允许直接删除，需要先停止并确认结束。

聊天原文、用户账号、模型 Key、服务器连接配置、论文资料和个人 Skill 保留。服务器上的项目源码、原始日志、权重和产物文件按已确认的范围保留，本模块不发起远端文件删除。维护者的应用排错日志及独立导出文件也不在数据库记录删除范围内。

## 后端流程

```text
DELETE 请求
   ↓
require_current_user 验证 Token，取得当前用户
   ↓
ExperimentPurgeRepository 在工作线程中执行
   ↓
校验归属，锁定实验和目标运行
   ↓
检查活动训练、未包含在范围内的派生运行、进行中的代码修改和报告投递
   ↓
按外键顺序删除关联数据
   ├─ 任意 SQL 失败 → 全部回滚，不返回删除成功
   └─ 全部成功 → 提交
                    ↓
              精确清理对应 Redis 投递消息
                    ↓
              返回 204，前端刷新列表
```

用户身份取自 Token，不接受请求体中的 user_id。删除前的查询和每条清理 SQL 都限定用户与目标范围，其他用户访问得到 404。

运行创建流程原本会锁定实验，删除沿用同一实验锁，随后锁定目标运行。这样新建运行、启动状态更新与删除有明确先后关系。没有关闭外键约束来强行删除。

## 数据库清理范围

| 数据 | 表 |
| --- | --- |
| 执行绑定与监控任务 | run_executions、run_monitor_tasks |
| 解析规则、采集游标、指标事件 | run_metric_parsers、run_metric_streams、run_metric_events |
| 事实报告、运行评测方案 | run_reports、run_evaluation_specs |
| 报告事件、Agent 任务 | event_outbox、agent_tasks |
| 模型分析、建议及工具依据 | analysis_results、suggestion_results、suggestion_evidence |
| 修改记录及授权关联 | code_changes、code_change_claims |
| 派生运行关联及启动关联 | revision_runs、revision_launch_claims |
| 与本次运行绑定的资料和建议 | research_references、research_advice |
| 会话运行关联、运行工具记录 | chat_run_bindings、指向目标运行的 chat_tool_calls |
| 对话训练计划及启动关联 | chat_training_plans、对应 training_launch_claims（已有级联外键清理） |
| 运行本身 | experiment_runs |

删除整个实验还会清除该实验尚未启动的训练计划、全部所属训练配置（包括先前已软删除的配置）、experiment_evaluation_specs 和 experiments 行。

“聊天原文保留”意味着用户之前已经收到的文字不会被改写；例如过去对话里引用过某个指标，那段历史文字仍存在。但它不再提供已删除报告、工具结果或运行记录的查询入口。

## 派生运行和活动处理

- 单独删除原始运行时，如果它仍被派生训练引用，返回 409，先删除派生运行即可。
- 删除整个实验时，属于该实验的原始运行和派生运行一起清理；若存在不在删除范围内的派生运行，会明确拒绝，而不会偷偷删除另一个实验的数据。
- 正在执行的代码修改或正在投递的报告事件会返回 409，等待处理结束后可以重试。
- 删除后，旧模型结果无法再通过原运行和任务的归属检查写回或重新生成已删除记录。

这些检查处理的是系统已有的训练、修改与任务交接，不增加新的审批工作流。

## Redis 与缓存

报告事件 Stream 中保存的是事件 ID。后端在事务提交前收集目标事件的 redis_message_id，提交成功后只对这些消息执行 XDEL，并从当前消费组执行 XACK，不清空整个 Redis 库或整个队列。

Redis 临时不可用时，数据库硬删除仍然生效；清理失败写入维护者日志。残留消息只有投递标识，消费者查不到 MySQL 中的原事件和报告就不会生成新的分析任务。因此，不能把 Redis 清理暂时失败误报成“数据库记录未删除”。

个人 Skill 的 Redis 1 号库不受影响。聊天正文和上下文缓存随保留的聊天原文继续存在；系统没有独立的运行报告正文 Redis 缓存需要清除。

## 接口文档

### 删除整个实验

```http
DELETE /experiments/{experiment_id}
Authorization: Bearer 登录凭证
```

### 删除单条运行

```http
DELETE /runs/{run_id}
Authorization: Bearer 登录凭证
```

均无请求体；UUID 支持接口现有的标准表示方式。成功返回 204，无响应正文，并设置 Cache-Control: no-store。

| 状态码 | 含义 |
| --- | --- |
| 204 | 目标及数据库关联数据已删除 |
| 401 | 未登录或登录失效 |
| 404 | 目标不存在或不属于当前用户 |
| 409 | 存在活动训练、代码修改、投递或范围之外的派生运行 |
| 422 | 路径 UUID 格式不正确 |
| 503 | 数据库等持久操作暂不可用；事务已回滚，稍后重试 |

重复删除已删除的目标返回 404，不会改动其他对象。

## 模块与技术栈

| 模块 | 作用 |
| --- | --- |
| app/api/experiment_delete_routes.py | FastAPI 路由、Token 依赖、错误映射、Redis 精确清理 |
| app/repositories/experiment_purge_repository.py | 归属与状态检查、数据库锁、单一事务、提交和回滚 |
| sql/purge_*.sql | 固定 SQL 查询及关联删除，业务值使用参数传递 |
| src/api/index.ts | deleteExperiment、deleteRun 请求 |
| src/views/TrainingView.vue | 确认框、按钮状态、成功刷新和失败保留卡片 |

沿用 Python asyncio.to_thread、mysql-connector、MySQL InnoDB 事务与外键、redis-py；前端沿用 Vue 3、TypeScript、Element Plus。没有新增数据库表、迁移或运行时依赖。

SQL 中的目标列只能由程序在 id 与 experiment_id 之间选择。SQL 文件单独保存；当前连接先选择目标数据库，再执行多表关联 DELETE，不改变其他连接的默认数据库。

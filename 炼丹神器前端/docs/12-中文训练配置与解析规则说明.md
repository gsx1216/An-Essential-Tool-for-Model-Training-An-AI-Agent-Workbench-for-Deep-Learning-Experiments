# 中文训练配置与解析规则说明

更新日期：2026-10-29。

## 页面现在展示什么

“训练任务配置”不再使用 DataTree 将接口对象逐字段展开，改为固定的中文业务视图：任务名称、所属实验名称、服务器名称、训练文件、运行环境、显卡、默认参数等。

任务 ID、实验 ID、服务器 ID、自动生成的脚本标识、源码哈希、存储快照、原始字段名和未选择展示的额外字段都不再出现在这个详情里。任务卡片也去掉了内部编号和自动生成的入口标识。同一“实验与训练”页的运行列表改用“训练运行”作为入口文字，不再显示数据库编号缩写。

实验、服务器名称先从已有列表解析；列表中没有时使用已有详情接口查询。无法读取名称时显示中文说明，不以数据库 ID 代替名称。关闭详情、切换任务时，旧请求不会重新打开或覆盖新详情。

字段标题和操作提示使用中文；用户自己命名的项目、文件名、参数值仍保留原文。比如训练文件 train.py 不会被改名。常见训练参数显示为“训练轮数”“每批样本数”“学习率”；不知道含义的自定义参数保留名称并标注为自定义，不猜测中文含义。

这里调整的是前端展示。接口仍保留定位和操作本人资源所需的 ID，数据库中的实际关联和既有鉴权没有改变；隐藏字段不等于新增管理员权限控制。此次只处理训练配置及相关采集规则表单，其他业务页的展示没有全局替换。

## 原来的规则配置，每一项是什么意思

先看普通日志中的一行：

```text
2026-10-29 20:37:46.633166 Epoch [037/300], Step [0001/0048], LR:0.0000500||sal_loss:1.711761
```

人可以读出：第 37 轮，计划共 300 轮；本轮第 1 批，共 48 批；学习率为 0.00005；打印的损失为 1.711761。程序需要一份明确的“取数说明”，这就是解析规则。

| 原配置字段 | 页面中文名称 | 实际作用 |
| --- | --- | --- |
| pattern | 日志匹配表达式 | 告诉系统怎样识别一行文字，以及从哪里取数字 |
| dataset | 所属数据集 | 给提取出的记录标注来源数据集，不是自动识别数据集文件 |
| split | 指标来自哪一组 | train 对应训练集，validation 对应验证集，test 对应测试集 |
| metrics | 要提取的指标 | 列出需要保存、绘图的数值名称，必须与表达式的命名标记对应 |

原来的最外层 `[...]` 表示“这里有多条规则”；每个 `{...}` 是一条规则。用户的两条规则分别识别训练 loss 行和 MAE 行。它们不是要求训练日志变成 JSON。

`dataset: "unspecified"` 的意思是“没有指定数据集”。现在页面里可以直接留空，保存时自动转换成这个约定值。如果知道真实来源，可以填写自己的数据集标识。

`metrics: ["sal_loss", "learning_rate"]` 表示保存两个数值：日志中名为 sal_loss 的损失值和 learning_rate 学习率。它不会自动算出新的损失。

第二条规则中的 `metrics: ["mae"]` 表示只提取当前 MAE。日志中的 bestMAE 和 bestEpoch 不会因为出现在同一行，就被一起保存。当前分组填写 validation 只是配置选择；若实际日志来源是测试集，应改选测试集，系统不会凭格式判断研究协议。

## 匹配表达式里的符号

这里使用 Python 的正则表达式，可以把它看成一份“固定文字 + 数字填空”的模板。下面展示的是表达式本身，旧 JSON 配置为了表示反斜杠会多写一层 `\`；现在中文表单不需要手工添加 JSON 转义。

| 写法 | 通俗含义 |
| --- | --- |
| `Epoch`、`Step`、`LR:` | 匹配日志里原样出现的固定文字 |
| `\s+` | 一个或多个空白字符 |
| `\s*` | 可以有空格，也可以没有 |
| `\d+` | 一个或多个数字 |
| `\[`、`\]` | 匹配日志里的方括号 |
| `(?P<epoch>\d+)` | 取出这里的整数，并命名为 epoch，也就是训练轮数 |
| `(?P<sal_loss>[-+0-9.eE]+)` | 取出这里的数字文本，命名为 sal_loss；支持小数或科学记数法，随后还有数值校验 |
| `\|\|` | 匹配日志中的两个竖线 |
| `^Epoch:` | 只匹配以 Epoch: 开头的行 |

所以第一条规则的意思是：找到包含 Epoch、Step、LR、sal_loss 的训练行，取出轮数、学习率、损失。时间戳不保存为指标，300 是总轮数也没有保存，批次数字在这条规则里仅用于识别行的结构。

第二条规则的意思是：找到以 Epoch: 开头的 MAE 行，取出当前训练轮数和 MAE。bestMAE、bestEpoch 等后续文字不参与本条提取。

两条示例都只命名了 epoch，没有单独命名 step，现有采集器会用 epoch 作为绘图步数。同一轮的两次 loss 打印会各保留一个点，不能把它们解释为该轮平均 loss，也不是全局批次步数。

## 现在如何在页面配置

1. 进入运行详情，点击“日志格式与采集规则”。
2. 点击“新增解析规则”，填写日志匹配表达式。
3. 数据集可留空；分组直接选择训练集、验证集或测试集。
4. 从中文选项中选择要提取的数值，也可以填写自定义指标名称。
5. 点击“保存并补采指标”。

已有规则会自动还原成表单。最多八条，可以单独删除。提交时页面会检查表达式和指标是否填写，再转换为原来的接口结构，因此不需要用户手写整段 JSON。

“填入通用示例”只增加一条匹配 step=1 loss=0.5 的通用规则，不会自动生成针对某个项目的解析器。未知日志仍需根据真实格式填写。结构化日志协议放到“给训练脚本开发者”折叠说明里，普通用户不必先阅读这段接口格式。

填写表达式时使用单个反斜杠，例如 `\d+`。只有在直接调用 JSON 接口时，JSON 字符串才需要写成 `\\d+`。中文表单会自动完成序列化转义。

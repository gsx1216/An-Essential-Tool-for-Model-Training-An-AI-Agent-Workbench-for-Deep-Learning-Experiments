# 模型直连修复与分析展示简化

日期：2026-10-30。

## 修复原因

本次失败日志的调用链为 OpenAIConnectionError → APIConnectionError → ConnectError，出错栈位于 http_proxy/start_tls。已保存 Key 的解密和主网络源码读取都成功，报告分析也已有成功结果；失败点在建议阶段访问模型 API 的网络连接。

使用无鉴权 GET https://api.deepseek.com/models 检查，直连能够建立 HTTPS，返回预期的 401。随后用修复后的模型网关和当前用户已保存的 Key 执行 SDK models.list()，成功返回模型列表。没有发送聊天、报告或源码生成请求，没有用新的模型回答验证产生 Token 用量。模型列表请求不证明余额足够，也不保证未来所有生成请求都成功。

## 后端改变

ModelGateway 同时为同步和异步 SDK 注入明确配置的 HTTPX 客户端，默认 trust_env=False，使模型访问不再继承桌面/启动进程的 HTTP_PROXY、HTTPS_PROXY 等环境代理。TLS 证书验证仍开启，没有修改系统代理或清空其他服务的环境变量。

get_model_trust_env() 从环境或 config/.env 读取 MODEL_TRUST_ENV，默认 false；确实需要代理的部署可以显式设为 true，其他值拒绝。现有 aclose() 通过两个 SDK 根客户端继续关闭其 HTTP 客户端。

config/.env.example 增加说明；本次没有改动真实 .env 的 Key、密码或系统代理。更改由 Uvicorn reload 加载，新请求创建新网关。已保存的失败任务不会自动变成功或自动重试，用户需点击运行页的“开始分析与建议”；已经成功的报告分析复用原结果。

技术栈：现有 Python、Pydantic 配置流程、python-dotenv、HTTPX、LangChain/DeepSeek/OpenAI 兼容 SDK；没有新增依赖。

## 前端改变

RunAgents.vue 不再用 DataTree 展示原始分析对象。页面分别列出：

- 分析结论的自然语言正文；
- 建议正文和验证方法；
- 必要的局限说明；
- 与具体代码建议对应的实际文件、行号、代码片段和修改方向。

移除 evidence_paths、text 字段标题、原始 source/facts、代码/论文内部引用对象、证据编号/哈希列表、全部工具记录抽屉及报告事件分发面板。同步移除页面不再需要的事件轮询、分页和查看工具记录请求。

内部证据、引用校验、归属检查、MySQL 审计记录和开发日志继续保留；不删除这些数据来改变展示。已有分析记录刷新即可按新方式展示，不需要为了样式重新调用模型。手动触发接口及请求体没有改变。

## 测试与实际验证

- 前端手动分析 5 项测试通过，新增断言：结论和验证方法可见，evidence_paths、JSON Pointer、内部事件 ID 和工具记录面板不可见。

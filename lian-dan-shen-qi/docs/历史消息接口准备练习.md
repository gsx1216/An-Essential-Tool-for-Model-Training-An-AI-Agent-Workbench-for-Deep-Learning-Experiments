## 先填写工厂：TODO 1～3

位置：app/api/dependencies.py 最下面的 get_chat_history_service()。导入和缓存装饰器已经准备好。

```text
读取后端数据库密码
  → MessageRepository(password)
  → ChatHistoryService(repository)
```

MessageRepository 是消息仓储，提供 load_history_page；SessionRepository 管理会话，LoginSessionRepository 管理登录凭证。

这次工厂不需要 TokenService，因为历史服务使用已经确认的用户 ID；Token 校验仍由已有的 require_current_user 完成。工厂不调用 load_history_page，不接收用户 ID，也不缓存具体用户的历史。

## 再填写响应模型：TODO 4～6

位置：app/api/schemas.py 最下面的 HistoryMessageResponse。

| 字段 | 类型 | 表示什么 |
| --- | --- | --- |
| seq | int | 当前会话内的消息序号 |
| role | str | 角色，例如 human、ai、system |
| content | str | 消息原始正文 |

三个字段都必填，不设置默认值。字段填好后可以删除 pass；pass 只是空语句，不会抛出异常。

一项响应的结构示例：

```json
{
  "seq": 1,
  "role": "human",
  "content": "你好"
}
```

HistoryMessageResponse 表示一条消息。未来接口返回 list[HistoryMessageResponse]，把数据库的每个 (seq, role, content) 元组转换成一个模型。空历史返回 []。

seq 从数据库读取，不用 uuid4 生成，也不用根据页面位置从1重新编号。content 保留原始空格、换行和代码缩进。

## 模块和包的职责

| 对象或模块 | 来源 | 本次作用 |
| --- | --- | --- |
| lru_cache | Python 标准库 functools | 复用工厂返回的服务对象，不缓存查询结果 |
| get_mysql_password | 项目 app.config | 读取后端配置中的数据库密码 |
| MessageRepository | 项目仓储模块 | 执行消息 SQL，校验归属和分页范围 |
| ChatHistoryService | 你完成的业务模块 | 校验 ID，使用工作线程读取一页历史并返回 |
| BaseModel | 第三方 Pydantic | 声明消息响应的字段及类型 |
| dependencies.py | 项目对象组装模块 | 向未来路由提供服务对象 |
| schemas.py | 项目数据结构模块 | 规定 HTTP 返回的数据形状 |

未来请求的 Token 由身份依赖转换为 current_user；路由将 current_user.user_id 交给服务。工厂和响应模型本身不负责登录验证。

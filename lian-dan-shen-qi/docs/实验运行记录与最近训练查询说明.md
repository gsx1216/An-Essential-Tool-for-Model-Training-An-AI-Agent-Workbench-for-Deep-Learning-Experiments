# 实验运行记录与最近训练查询说明

日期：2026-10-25。项目：E:\code\LangChian_New。

## 1. 本阶段实现与边界

新增 experiment_runs 表和四个接口：为自己的实验创建运行记录、分页查看运行、读取运行详情、查询本人最近提交的训练运行。保存实验定义和参数快照，创建请求具备幂等性。

创建后的状态为 created，表示“记录已创建”，不是训练已经排队或启动。本阶段不连接远程服务器、不执行脚本、不生成训练指标，也没有把查询接口接成聊天模型工具。不能因为接口可以查询最近运行，就认为在普通聊天中提问会自动读日志。

后续将基于该记录接执行器、服务器连接、指标和报告，再把查询与日志工具接入聊天。远程连接、文献检索及有依据的建议是已确认要求，详见 [服务器连接与有据建议设计](服务器连接与有据建议设计.md)。

## 2. 如何启动并在 /docs 测试

已有 langchain 环境和本机 MySQL，不新增依赖或收费服务。服务器配置仍使用 MYSQL_PASSWORD，创建运行不需要个人模型 Key。

```powershell
Set-Location E:\code\LangChian_New

# 补实验父表归属索引和运行表，不回填聊天，不启动训练。
python -m app.database --experiment-run-schema

python -m uvicorn app.main:app --reload
```

打开 http://127.0.0.1:8000/docs，登录后点击 Authorize，填入 access_token。先通过“实验管理”创建 kind=training 的实验，复制 experiment_id；已有的 training 实验也可以使用。

在“实验运行记录”的 POST /experiments/{experiment_id}/runs 中填写该 ID。请求示例：

```json
{
  "request_id": "430390d7-1ece-4e63-ae20-2043b057e9c2",
  "parameters": {
    "learning_rate": 0.001,
    "epochs": 10,
    "batch_size": 32,
    "seed": 42
  }
}
```

示例请求编号仅供第一次测试。同一次提交因网络问题重试时复用它；打算创建新运行时必须换一个编号。可在终端生成：

```powershell
python -c "from uuid import uuid4; print(uuid4())"
```

首次返回 201，格式为 {"run": {...}, "replayed": false}。run 包含服务端生成的 run_id、实验标题/类型/说明快照、parameters、status 和 UTC 时间；Location 指向 /runs/{run_id}。

再次提交相同编号和相同参数，返回 200、replayed=true 和原运行。JSON 对象键的顺序不同仍视为同一配置；同一用户复用编号却修改参数或换另一个实验，返回 409。不同用户的请求编号互不冲突。

接着测试：

| 接口 | 用途与期望 |
| --- | --- |
| GET /experiments/{experiment_id}/runs | 分页列表，默认 limit=20，最大 100；下一页传 next_cursor 到 before_id |
| GET /runs/{run_id} | 查看本人运行详情和参数快照 |
| GET /runs/latest-training | 返回本人最近提交的 training 运行；没有记录为 {"run": null} |
| GET /runs/latest-training?experiment_id=实验UUID | 只在本人指定实验中查训练运行 |
| GET /runs/latest-training?status=succeeded | 显式查最近提交且已成功的训练运行 |

最新查询也支持 status=created、queued、running、failed、cancelled。当前没有执行器，因此你创建的正常记录应保持 created，has_logs=false、has_result=false、result_version=0；筛选 succeeded 通常返回空，这是正常结果。

最新的含义是“创建时间最晚，时间相同按 ID 排序”，不是“完成时间最晚”。默认不筛选成功：最新仍在运行或失败时，都应返回那一次；普通 script 运行不混入训练结果。若某个有效实验没有训练运行，也返回 run=null；实验不存在或属于他人则返回 404。

隔离练习应用也支持这些接口：

```powershell
python -m scripts.run_chat_api_demo --port 8001
```

在 http://127.0.0.1:8001/docs 重新注册登录。它使用独立临时库、禁止真实模型客户端，Ctrl+C 正常退出时清理本次数据；正式库 Token 不适用于临时库。

## 3. 表中每类字段存什么

| 字段 | 作用 |
| --- | --- |
| id / experiment_id / user_id | 运行 UUID、所属实验、所属用户 |
| request_id | 本人一次创建请求的稳定编号，和 run_id 用途不同 |
| input_digest | 实验 ID 与规范参数文本的 SHA-256，判定重复请求是否改变输入；不公开返回 |
| experiment_title / experiment_kind / experiment_description | 创建运行时的实验定义快照，后续定义变更不覆盖旧运行 |
| parameters_json | 规范 JSON 文本快照，TEXT 存储，数据库检查合法 JSON 对象且不超过 32768 字节 |
| status | created、queued、running、succeeded、failed、cancelled |
| created_at / updated_at | UTC 时间，创建 SQL 显式写 UTC_TIMESTAMP(6) |
| started_at / finished_at / exit_code / error_code | 后端执行器未来写入的运行状态元数据；目前为空 |
| log_ref / result_ref / result_version | 预留后端受控日志/结果引用及版本；客户端不能写，原始引用不公开 |

公开响应只用 has_logs、has_result、result_version 表示结果是否存在，不向客户端返回内部文件路径。列表不返回完整参数和实验说明，点击详情再加载。

这里 user_id 也放在运行表中，便于为“本人最近训练”建立直接索引；同时用复合外键 `(experiment_id, user_id)` 引用 experiments 的 `(id, user_id)`，防止运行的用户与实验用户不一致。

为此新建库中的 experiments 增加 uq_experiments_id_owner。已有项目库由选择性迁移检查并补上该唯一键；这会增加索引，不改变用户、实验、聊天记录。父键和外键列的类型、顺序及索引必须匹配。[MySQL 外键说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)

主要索引：本人请求唯一键、实验范围创建时间/ID 分页索引、本人训练类型创建时间/ID 索引，以及附带状态的最新查询索引。具体查询性能仍需结合实际数据测量。

状态 CHECK 限制时间与退出码的一致性，例如 running 需要开始时间，succeeded 需要开始/结束时间和退出码 0。它不是状态机调度器：真正的状态迁移、租约、心跳、幂等启动与进程恢复留给执行器阶段。

## 4. 创建请求怎样通过校验并保存

```text
HTTPBearer 提取 Token
  → require_current_user 校验登录，取得 current_user.user_id
  → CreateRunRequest 校验请求 UUID、对象结构和额外字段
  → ExperimentRunService 校验 ID 与参数并复制参数快照
  → await asyncio.to_thread(仓储.create_run, ...)
  → 仓储再次保护直接调用的输入边界
  → 短事务 FOR SHARE 锁定该用户的实验
  → INSERT SELECT 从实验定义复制快照并创建 created 记录
  → 读回并校验快照，commit 后返回 201
```

归属锁使用共享锁，允许同一实验创建不同运行，同时保护创建期间实验定义不被改动。模型或训练执行不发生在这个事务里。

如果唯一键发现同一用户请求编号已存在，先回滚本次插入，关闭该连接，再开新的读取事务查询旧运行。这样可以看到另一个请求刚提交的记录。实验与参数摘要一致就返回原记录，状态不重置；不一致返回 409。

没有对应请求记录的其他唯一冲突不伪装成功。连接故障、死锁等返回安全 503，调用方可沿用原 request_id 重试；即使上次已经提交但响应丢失，也不会因此创建另一条运行。

参数快照用规范文本保留确切序列化结果，避免把数据库原生 JSON 的规范化行为当成原始文本不变性保证。[MySQL JSON 说明](https://dev.mysql.com/doc/refman/8.0/en/json.html)

## 5. 参数校验具体检查什么

顶层必须为对象。只支持 JSON 的字符串、整数、有限浮点数、布尔、null、列表与对象，不接受 tuple、set、bytes 或 Python 实例。

- 规范 JSON UTF-8 总大小最多 32768 字节，包含键、标点和转义。
- 嵌套深度最多 8（顶层为 0），最多 1000 个被遍历的值节点。
- 键为 1～128 字符字符串，拒绝循环引用及非法 Unicode 代理字符。
- 整数范围为 -2^63～2^64-1；拒绝 NaN 和无穷大。
- 常见 password、api_key、access_token 等凭据字段拒绝保存；max_tokens、tokenizer 等正常参数不受此规则影响。这不是能识别所有秘密的扫描器，参数快照不应承载凭据。

规范化排序后计算摘要；JSON 键顺序不影响幂等，但不同数值表示或类型可能被视为不同输入，例如 1 和 1.0、true 和 1。读取详情会复核文本格式和摘要，异常转换为 RunStorageError，防止把损坏快照当作正常数据返回。

RunRecord 内保存不可变字符串，parameters 属性每次解析生成新字典。调用方修改返回字典，不能改写已保存的快照。参数现在只做记录，不会 eval/exec，也不会作为 shell 命令执行；将来由受控脚本适配器解释允许的训练参数。

身份链沿用已有实现：get_bearer_token 提取凭证；CurrentUserService 计算哈希；LoginSessionRepository 查未过期且未撤销的登录和有效用户。它不在每次运行查询时重新核对明文密码。

每个仓储方法都校验当前身份及目标归属。详情和最近查询还 JOIN experiments 核对父子归属。列表先在只读快照确认实验属于当前用户，再校验游标同时属于该实验，按创建时间和 ID 读取 limit+1 条。

静态 /runs/latest-training 声明在 /runs/{run_id} 前，避免被当成 UUID。未指定状态、仅指定状态、仅指定实验、两者都指定分别使用固定 SQL 文件，不拼接用户输入为 SQL 片段。

日志沿用 logged_operation 和 log_failure，记录源码位置、请求关联、耗时、异常类型和安全原因，不序列化参数、快照、密码、Token 或模型 Key。

## 8. 状态码与测试用例

| 场景 | 预期 |
| --- | --- |
| 新请求创建 | 201，replayed=false |
| 相同请求编号、相同配置重试 | 200，原 run_id，replayed=true |
| 同一用户编号换参数或实验 | 409，不覆盖原记录 |
| 列表/详情/最近查询成功 | 200，空列表或 run=null 正常 |
| 参数类型合法但超预算、含不支持数据或凭据字段 | 400 |
| Token 缺失、失效、过期、已退出 | 401 |
| 实验/运行/游标不存在或无权访问 | 404，不暴露他人记录是否存在 |
| UUID 错误、缺少字段、额外 status/user_id/command、分页越界 | 422，全局处理器不回显原输入 |
| 数据库或持久化快照异常 | 503，请稍后重试 |

## 9. 迁移与下一阶段

选择性迁移仅确认实验表、补归属唯一索引并创建运行表。若存在同名但错误结构的索引，会拒绝继续，不自动删索引重建。DDL 有隐式提交，不能假定后续失败会撤销已完成的建表或索引；确认原因后可重试迁移。

容量检查同步增加 experiment_runs，目前固定跟踪九张业务表。历史报告仍是生成时的范围。

下一阶段实现 Runner 和执行目标：服务器连接、受控脚本、幂等启动、状态迁移、日志、心跳及停止/恢复。随后增加指标与结果报告、会话关联及工具调用，让全新聊天“最近一次训练怎么样”真正查询这些记录并读取证据。

研究与建议模块还须联网检索相关论文/技术文档，保存来源和适用条件，才能形成有据的修改提案。当前这一阶段只建立运行基础，不能标记整套 Agent 系统已经完成。

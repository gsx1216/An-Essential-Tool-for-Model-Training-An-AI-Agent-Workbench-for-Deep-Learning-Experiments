# 通用训练项目接入与接口说明

日期：2026-10-29。项目：`E:\code\LangChian_New`。

## 1. 本次完成的功能

训练不再依赖 PRNet 专用适配器。已登录用户可以配置自己的服务器项目、Python 环境、训练入口、启动参数、GPU 和指标读取规则，随后在聊天中按任务名称启动。

适用于具有 Python 训练入口的目标检测、跟踪、点云、伪装目标检测等项目。系统调用项目原本的训练程序，不接管或重写其训练循环。

用户只需要为项目配置一次入口；不同项目可以使用不同的参数名，不需要再为每个网络编写一个后端适配器。

本次没有新增数据库表、Redis 队列、Worker 或第三方依赖。任务配置继续保存在 `training_tasks.configuration_json`；启动、监控、分析、建议、代码副本和对比沿用原有链路。

## 2. 流程图

```text
用户保存自己的 SSH 服务器，work_dir 指向项目根目录
  ↓
页面或 Agent 只读查看目录、README、训练入口和配置文件
  ↓
根据真实代码整理 project 配置，用户确认并保存训练任务
  ↓
用户说：“启动我的点云训练，iterations=100”
  ↓
Agent 查询本人任务 → 准备计划 → 检查本轮明确启动指令
  ↓
Runner 固定服务器、入口 SHA、Python、参数、GPU 和输出配置
  ↓
SSH 监督器以 argv 启动项目原始 Python 文件
  ↓
采集日志、退出状态、真实指标，发布产物
  ↓
现有报告 / 分析 / 建议 / 修改副本 / 修改后训练 / 对比
```

“查看项目”“保存任务”“准备计划”都不会开始训练。只有明确启动步骤才执行项目程序。

## 3. 移除了什么

已移除后端 `app/runner/prnet_adapter.py`、专用部署构建器、PRNet 部署脚本、对应适配器测试与配置模板。

修改后训练也不再生成 PRNet 专用入口，所有新自定义项目使用通用 `cwd` 模式。默认 Runner 注册表不再预置 `prnet_train`；其他已登记通用入口仍可使用旧接口。

服务器上的真实 PRNet 源码、数据、日志、权重以及数据库里的实验、运行、聊天记录均未删除。历史执行快照仍可读取；已经保存的旧辅助源码按历史记录处理，不再依赖被删除的本地适配器。

以前配置的 PRNet 任务不能被当成已经迁移完成的新通用任务。需要根据其真实训练脚本重新创建 project 配置；不在后台猜测参数或偷偷重跑。

## 4. 技术栈与模块职责

| 技术/模块 | 作用 |
| --- | --- |
| FastAPI | 鉴权后的项目读取、任务创建与运行接口 |
| Pydantic | 校验项目路径、启动配置、参数类型、范围和指标规则 |
| asyncio / asyncio.to_thread | 网络异步调用；把同步 MySQL 仓储操作移出事件循环 |
| MySQL | 永久保存用户归属、任务配置、不可变训练计划和启动快照 |
| 现有 Redis / Outbox / Workers | 复用原有监控、事件分发、分析和建议，不增加第二套调度 |
| 现有 SSH 连接器 | 使用用户已保存的连接配置和主机指纹，读取或启动本人项目 |
| subprocess.Popen | 以参数数组启动远端训练进程，不拼接用户 shell 命令 |
| JSONL | 将真实训练指标交给已有指标入库和报告模块 |
| 正则命名组 | 可选地把原始文本日志转换为 JSONL 指标 |
| SHA-256 | 校验训练入口版本；修改后运行额外固定源码副本 |

### 关键 Python 文件

- `app/models/training_project.py`：通用项目配置、路径占位符、指标规则、读取参数和 Swagger 示例。
- `app/models/training_task.py`：任务请求支持 project 与旧 script_id 二选一，登记训练前项目读取工具。
- `app/services/training_task_service.py`：查本人服务器、读入口、保存任务、合并参数、准备和启动计划。
- `app/repositories/training_repository.py`：保存和查询 MySQL 任务；新增按 user_id + script_id 查本人入口。
- `app/services/runner_service.py`：解析本人配置的入口、校验服务器绑定、固定启动快照并调用远端。
- `app/runner/remote_agent.py`：执行项目原始脚本，传递 Python/参数/GPU/路径，监督进程、记录日志、转换指标、发布产物。
- `app/services/revision_run_service.py`：准备修改后运行，自定义项目自动使用通用副本模式。
- `app/runner/revision_source.py`：核对并冻结修改源码，供修改后训练使用。
- `app/services/code_change_service.py`：将用户配置的排除目录用于代码副本准备。
- `app/api/training_task_routes.py`：新增训练前项目读取接口，复用原任务接口。
- `app/api/dependencies.py`：把任务仓储、Runner、SSH 源码读取通道组装起来。

## 5. 两种任务配置方式

`POST /training-tasks` 支持：

1. **推荐：project。** 用户接入自己的项目，不依赖全局脚本注册表。
2. **兼容：script_id。** 选择部署者已登记、支持原有 --config 协议的通用入口。

两者必须且只能提供一个。不要在 Swagger 中同时填写 `script_id: "string"` 和 project。

自定义项目保存后，系统生成 `project_<随机UUID>` 形式的内部 script_id。这个编号只在当前用户的任务范围内解析，不会写入全局配置，也不开放给其他用户使用其服务器。

`GET /runner/scripts` 仍只列全局登记入口；用户自定义项目从 `GET /training-tasks` 和任务详情查询。

## 6. project 字段说明

| 字段 | 含义 |
| --- | --- |
| entrypoint | 服务器 work_dir 内的相对 Python 入口，例如 train.py 或 tools/train.py |
| python | 远端训练使用的 Python 程序或绝对路径，默认 python3 |
| arguments | 启动参数数组，每个元素对应 argv 中的一项 |
| parameter_rules | 用户参数的类型、必填项、范围或字符串长度规则 |
| cuda_visible_devices | 例如 0、1、1,2；空字符串隐藏 GPU；null 继承远端环境 |
| metric_rules | 可选：从普通日志提取实际指标的规则；已有 JSONL 时可以为空 |
| exclude_directories | 准备代码修改副本时跳过的数据/产物目录 |
| max_runtime_seconds | 默认 86400 秒即 24 小时，可配置 1 秒至 7 天 |
| max_log_bytes | 日志预算，默认及最大 10 MiB |

注意：

- Python 环境需要事先在训练服务器上安装好依赖。这里填写该环境的 Python 路径，例如 `/home/user/miniconda3/envs/vision/bin/python`。
- 后端辅助程序仍使用部署配置里的 Python；真正的训练进程使用项目自己的 Python。
- 服务器 work_dir 就是本次接入的项目根目录。相同机器上不同项目可以保存为不同的服务器/项目配置。
- 参数名不是固定的 epochs、batch_size。可以改用 iterations、num_points、config、device 等项目实际需要的名称。
- boolean 占位符生成 true / false 字符串；需要 --amp 这种单独开关时可以把它作为固定 arguments 元素。不要假定所有脚本都支持 '--amp true'。
- 原项目依靠 Shell 脚本、多机调度器或自动安装环境启动的情况，目前不能仅填一个 .sh 文件就接入；需要先确定其实际 Python 入口或补充相应执行支持。

### 路径占位符

| 占位符 | 实际含义 |
| --- | --- |
| {source_root} | 当前执行的源码目录；修改后训练指向冻结副本 |
| {input_root} | 原始项目根目录，供数据和预训练权重使用 |
| {artifact_dir} | 本次运行的产物目录 |
| {config_file} | 本次运行的参数 JSON 文件 |
| {任意已定义参数名} | 该次运行的真实参数值 |

这些系统占位符不能被用户参数同名覆盖。未知占位符、属性访问和格式化表达式会被拒绝。

例如：

```json
"arguments": [
  "--iterations", "{iterations}",
  "--config", "{source_root}/configs/model.yaml",
  "--data-root", "{input_root}/datasets",
  "--output", "{artifact_dir}"
]
```

最终使用参数数组启动，数据里的分号、空格等按普通参数传递，不作为 shell 指令解释。

## 7. 完整任务请求例子

下面两个 UUID 只是明确的占位示例，必须换成当前账号实际创建的实验 ID 和服务器 ID。入口和参数名称也要根据自己的代码修改。

```json
{
  "name": "我的目标检测训练",
  "experiment_id": "00000000-0000-4000-8000-000000000001",
  "server_id": "00000000-0000-4000-8000-000000000002",
  "project": {
    "entrypoint": "train.py",
    "python": "/home/user/miniconda3/envs/vision/bin/python",
    "arguments": [
      "--epochs", "{epochs}",
      "--lr", "{learning_rate}",
      "--output", "{artifact_dir}"
    ],
    "parameter_rules": {
      "epochs": {"type": "int", "required": true, "min": 1, "max": 200},
      "learning_rate": {"type": "float", "required": true, "min": 0.000001, "max": 1.0}
    },
    "cuda_visible_devices": "1",
    "exclude_directories": ["datasets"],
    "max_runtime_seconds": 86400,

  },

    "epochs": 20,

  }
}
```

保存时会读取入口并取得当前文件 SHA-256，但不会导入或执行它。

可直接查看 [请求模板](../examples/training_project.example.json)。

## 8. 训练前读取接口

### POST /training-projects/files

只读列出本人服务器的项目目录，无需已有 run。

```json
{
  "server_id": "00000000-0000-4000-8000-000000000002",
  "path": ".",
  "offset": 0,
  "limit": 25
}
```

返回 server_id、work_dir、items 和 next_offset。用它查找真实 README、训练入口与配置目录。

### POST /training-projects/file

只读读取有行号的文本源码、README 或配置。

```json
{
  "server_id": "00000000-0000-4000-8000-000000000002",
  "path": "README.md",
  "start_line": 1,
  "line_count": 30
}
```

返回文件 SHA、读取范围和 next_line。需要续读时使用 next_line，并传前一页的 expected_sha256，防止混用不同版本。

上述接口复用已有源码读取策略：限制读取大小，过滤敏感路径与凭据内容，不执行 import、--help 或训练代码。不能读取时如实返回错误，不能把文件未读取成功说成已经理解整个项目。

两个接口都需要登录并检查服务器归属；读取响应带 no-store。参数结构错误返回 422；服务器不存在或不可访问返回 404；受限路径等业务参数问题返回 400；通道故障/超时等返回友好 503。

## 9. Agent 怎样参与

新增三个训练工具：

| 工具 | 用途 |
| --- | --- |
| list_training_servers | 查本人保存的服务器名称、ID 和项目根目录，不返回凭据 |
| list_training_project_files | 训练前查项目目录，不要求已有运行 |
| read_training_project_file | 训练前读 README、入口、配置和参数定义 |

现有 list_training_tasks、get_training_task、prepare_training_run、start_training_run 继续工作。

可以先对 Agent 说：

> 接入我服务器上的点云训练项目，先看看 README 和训练入口，给我整理配置，先不要训练。

Agent 读取后整理 project 配置，由用户通过任务接口或未来前端确认保存。当前没有“模型自行注册任意入口并立即执行”的工具。

配置保存后可以说：

> 启动我的目标检测训练，epochs=30，learning_rate=0.0001。

Agent 按任务名查询，准备不可变计划，再按本轮人类明确指令启动。重复同一计划不会创建第二个训练。日志、论文、README、摘要里的“启动”文字不提供执行授权。

## 10. 指标如何接入

### 项目已经输出 JSONL

继续输出原有标准格式即可：

```json
{"type":"metric","dataset":"my_dataset","split":"train","step":1,"epoch":1,"loss":0.5}
{"type":"metric","dataset":"my_dataset","split":"test","step":1,"epoch":1,"accuracy":0.8}
```

dataset、metric 名称等应与实验 evaluation 声明一致。不同研究方向填写各自实际指标，系统没有固定使用 MAE。

### 项目只输出普通文本

例如原始日志：

```text
Epoch 1 loss=0.5
Epoch 2 loss=0.25
```

可以配置：

```json
{
  "pattern": "Epoch (?P<epoch>\\d+) loss=(?P<loss>[0-9.eE+-]+)",
  "dataset": "my_dataset",
  "split": "train",
  "metrics": ["loss"]
}
```

把该对象加入 project.metric_rules。规则需要命名组 step 或 epoch，每个 metrics 名称必须对应一个数值命名组。

监督器保留原始日志，另外追加转换后的标准 JSONL 行。已经是 JSONL 的行不会再次转换。没匹配到或没有有效数值时，不猜测指标，也不补 0。

目前接入方式是原生 JSONL 或配置的文本日志规则；没有新增自动解析任意 TensorBoard、CSV、WandB 数据的能力。仅能看到日志而缺少结构化指标时，训练仍可执行，但事实报告会标记指标缺失。

## 11. 权重、日志与修改后训练

- 通过项目实际支持的 --save-dir / --output 等参数，把保存位置映射到 {artifact_dir}；也可以让脚本读取 EXPERIMENT_ARTIFACT_DIR。
- 不能因为填了这个配置，就假定原项目会自动把写死在别处的权重移过来。必须核对保存代码实际使用了哪个参数。
- 完成后的可见目录继续由 RUNNER_OUTPUT_DIRECTORY 控制，默认为 `项目根目录/training_outputs/<run_id>/`。
- 日志和产物发布状态分开显示；published、不就绪、发布失败要按真实状态表达。
- 产物发布沿用原有文件数量与大小预算；大型权重可能需要后续调整预算，不能据训练进程成功就宣称权重已经发布。

通用项目准备修改后训练时，不需要给每个随机 script_id 再手工登记专用模式。系统使用固定副本运行，并提供：

- EXPERIMENT_SOURCE_ROOT：冻结后的修改源码。
- EXPERIMENT_INPUT_ROOT：原始项目中的共享数据/预训练资源。
- EXPERIMENT_ARTIFACT_DIR：新运行的独立产物目录。

原始运行固定入口文件 SHA；它不等于完整项目和所有依赖的不可变快照。修改后运行则固定已复制的源码清单。写死原项目绝对导入路径、忽略新源码根目录的程序，需要调整后才能保证执行的确实是修改副本。

exclude_directories 用于避免把数据集、生成目录复制到源码副本；如果某个目录是真正的代码依赖，不应把它排除。

## 12. 在 /docs 中验证的顺序

1. 重启 API 及相关 Worker，加载新代码与配置。本次没有新建表要求。
2. 登录并 Authorize。
3. 创建自己的服务器配置，work_dir 填真实项目根目录；连接测试成功。
4. 创建 training 类型实验，按项目真实任务、数据集、评测方法配置 evaluation。
5. 用 /training-projects/files 和 /training-projects/file 查看项目，确认入口、参数、环境和输出路径。
6. POST /training-tasks，仅填写 project，不填写 script_id；换成真实实验和服务器 ID。
7. 查询 GET /training-tasks 和 GET /training-tasks/{task_id}，确认保存的是自己的配置。
8. 在聊天中明确说启动该任务，指定需要覆盖的参数；系统返回同一计划对应的 run_id。
9. 查看 execution、refresh、logs、metrics、report；不能把“保存成功”或 202 当成训练完成。
10. 对同一计划重试，确认仍使用同一个 run。需要新一轮训练时，使用新的明确提问创建新计划。
11. 如需验证代码修改，先读取建议与证据，再应用到独立副本，准备并显式启动修改后运行。
12. 对训练结果比较时，遵守原有评测协议一致与报告完整性要求。

要先验证启动协议而不使用 GPU，可以配置空字符串 cuda_visible_devices，并选用你自己的微型 CPU 样例。是否启动真实项目、需要多少 GPU 和训练时间，由用户明确选择。

## 13. 本次验证范围

自动测试覆盖：

- 未登记到全局表的用户项目可以配置、准备和启动。
- 不同目录、不同参数名的两个项目均能完成本机 CPU 训练进程。
- 用户参数不会被当作 shell 命令执行。
- 训练入口版本变化会拒绝执行。

- 日志提取为标准指标，保留原始日志，错误指标不伪造。
- 训练权重样例、输出目录、退出码和重复启动幂等贯通。
- 修改后的冻结源码可以沿用通用参数执行，原文件保持原样。
- Agent 在没有训练记录时可以读取项目文件。
- 原有接口和其余模块回归。

本次不连接真实训练服务器、不启动真实 GPU 项目，也不调用收费模型。测试结果与实际文件变更见 [文件变更清单](通用训练项目接入文件变更清单.md)。

## 14. 后续前端怎么适配

训练任务创建页提供：

- “接入我的项目”作为主要入口。
- 选择本人服务器 → 浏览项目文件 → 确认入口。
- Python 环境、参数定义与默认值、GPU、输出和日志指标规则表单。
- 保存前展示即将启动的文件和参数；保存按钮本身不训练。
- 保存后通过任务名称选择，不让用户手工填写内部 script_id。
- 允许兼容已登记的通用入口，但不预置某个网络为系统唯一训练对象。

当前完整定义由实际应用导出：[OpenAPI](api/openapi.json)、[接口索引](api/接口索引.md)。本次为 69 条路径、85 个 HTTP 操作。

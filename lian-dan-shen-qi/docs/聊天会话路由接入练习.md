## 为什么列表需要转换

仓储返回的是 `[(会话ID, 标题), ...]`，接口响应约定的是带字段名的数据。

```python
# 这是结构示例，实际 ID 来自数据库。
[
    {"session_id": "某个会话UUID", "title": "实验一"},
    {"session_id": "另一个会话UUID", "title": "实验二"},
]
```

可以先创建一个空列表，for 遍历时分别取 session_id、title，构造响应模型并 append，循环结束后 return。只有一条记录时也返回列表；没有记录时返回 []。

## 身份从哪里来

`current_user: UserResponse = Depends(require_current_user)` 要求 FastAPI 先确认 Token 有效，再把用户信息交给路由。`service = Depends(get_chat_session_service)` 提供业务对象。

这两个依赖分别提供“当前请求是谁”和“调用哪个服务”。它们不是继承关系。路由中不能使用自己输入或写死的 user_id；只能把 current_user.user_id 传给服务。

创建请求中的 title 来自 JSON；删除的 session_id 来自 URL 路径。用户名、密码和 Token 不出现在这三个接口的响应中。

## 三条路由写完后如何挂载

main.py 已由你完成挂载。对应的导入为：

```python
from app.api.session_routes import router as session_router
```

在已有 app.include_router(auth_router) 附近注册：

```python
app.include_router(session_router)
```

不要新建第二个 FastAPI 对象，也不要删除原有认证路由。注册后重载服务，Swagger 才会出现三个会话接口。路由函数中的 `""` 表示使用前缀本身，创建和列表路径均为 /sessions；删除路径为 /sessions/{session_id}。

## 写完后的验收用例

| 场景 | 预期 |
| --- | --- |
| 没有 Token、无效或已撤销 Token | 401 |
| 登录后 POST /sessions，正文 {} | 201，返回新 UUID |
| POST /sessions，标题两端有空白 | 201，数据库和后续列表保存规范后的标题 |
| POST /sessions，标题空白或超过200字符 | 400 |
| POST /sessions，正文额外传 user_id | 422，不创建会话 |
| GET /sessions | 200，返回自己的全部会话；无会话为 [] |
| 两个账号各自创建并查询 | 只能看到自己的会话 |
| GET /sessions?user_id=他人编号 | 仍只能看到 Token 对应用户的数据 |
| 删除自己的会话 | 204、空正文；会话、消息和轮次同时删除 |
| 重复删除或删除他人的会话 | 同一个404提示 |
| 删除路径不是合法 UUID | 400 |
| 数据库故障 | 503，只返回“请稍后重试。” |
| 未预期程序异常 | 全局中间件返回通用500，并记录日志 |

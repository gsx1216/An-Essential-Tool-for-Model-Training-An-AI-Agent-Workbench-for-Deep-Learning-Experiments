# 用户认证第一步：密码与注册

本步完成密码哈希工具、用户密码字段的兼容迁移、注册写入与认证读取的仓储方法。AuthService 的业务方法留给你手写。尚未开放登录接口或签发登录凭证。

## 三种凭据分别处理

| 凭据 | 保存位置 |
| --- | --- |
| 后端连接 MySQL 的密码 | 服务器环境变量或 config/.env |
| 用户登录密码 | users.password_hash，只保存 Argon2id 哈希 |
| 用户模型 API Key | 后续通过已鉴权接口提交，加密保存到用户配置表 |

不要把用户登录密码、数据库密码、模型 Key 当成同一个 password。

## 数据迁移

新库的 init.sql 已包含 password_hash；旧库使用：

```powershell
python -m app.database --user-password-schema
```

该命令只补 users.password_hash，不依赖旧会话失效归属问题是否已清理。重复运行允许，已有用户记录和密码不会被修改。旧用户 password_hash 为 NULL，不能用默认密码登录，后续需要明确的密码设置/重置流程。

原 create_user(username) 仅兼容开发测试脚本，创建的账号没有登录密码。正式注册必须调用 create_registered_user(username, password_hash)。

## 密码工具

app/security/passwords.py 的 PasswordService 提供：

- hash_password(password)：验证本项目注册密码长度后生成 Argon2id 哈希。
- verify_password(password, password_hash)：验证输入是否匹配；错误密码、缺失或无效哈希返回 False。

按项目要求，当前注册密码长度为 8～32 个字符，允许 Unicode 和空格，不自动 strip 或截断。盐值由库自动随机生成，因此相同密码的两次哈希也不同。密码哈希不是可以解密的密文，验证由库完成。

登录验证兼容此前已经保存的长密码哈希，避免修改注册长度后使旧账号无法登录；新注册仍严格执行 8～32 个字符。

没有用户或旧账号没密码时仍做一次虚拟验证，以减小耗时差异；这不代替后续接口的登录限流、防暴力破解和通用错误提示。

哈希计算是同步且耗费 CPU 的操作，在异步业务中使用 asyncio.to_thread。PasswordService 宜在服务初始化时创建后复用，不要每条消息重新创建。

## 你现在手写 register

打开 app/services/auth_service.py，只填 register：

1. 使用 normalize_required_text 处理用户名，最大长度为 64。
2. 用 asyncio.to_thread 调用 self.password_service.hash_password，取得 password_hash。
3. 用 asyncio.to_thread 调用 self.repository.create_registered_user，取得 user_id。
4. 返回 (user_id, username)。

密码不使用 normalize_required_text，因为该函数会 strip，可能改变密码。

仓储已经处理重复用户名、参数化 SQL 和事务回滚。此阶段业务异常向上传递，等编写接口时统一映射到响应。

先完成注册，检查通过后再写 authenticate。认证查询的内部元组为 (id, username, password_hash)，不可原样返回给前端。authenticate 只核对身份，之后还需要登录凭证、接口鉴权，才能安全地按用户读取模型 Key。

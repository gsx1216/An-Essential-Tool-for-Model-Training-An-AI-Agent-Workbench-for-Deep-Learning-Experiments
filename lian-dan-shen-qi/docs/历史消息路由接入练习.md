## 本次执行顺序

1. main.py 的 include_router 将 router 的前缀和路径组合为 GET /sessions/{session_id}/messages；@router.get 把这个请求映射到 read_chat_history。
2. auth_dependencies.py 从 Authorization 提取 Bearer Token，调用 CurrentUserService 和登录仓储，确认登录未过期或撤销，得到 UserResponse。URL 中额外的 user_id 不能替代这个身份。
3. FastAPI 将路径放进 session_id，将查询字符串转换成 after_seq、limit；Query 校验类型和范围。不合法时返回422，路由业务函数不会执行。
4. dependencies.py 通过 get_chat_history_service 提供 MessageRepository 和 ChatHistoryService 组成的对象。缓存的是服务对象，不是当前用户、查询结果或共享数据库连接。
5. history_routes.py await service.load_history_page(...)。async 方法调用本身先产生协程对象，await 等待执行完成后才能拿到消息列表；没有 await 时，for 会尝试遍历协程并报 TypeError，业务中的异常也没有机会在当前 try 中抛出。
6. chat_history_service.py 校验正整数用户ID、规范UUID；asyncio.to_thread 把同步的仓储查询放到工作线程，await 等待结果。这里已经是异步业务方法，路由不需要再次用 to_thread 包住它。
7. message_repository.py 再校验分页参数并确认会话属于该用户；database.py 创建本次连接，load_history_page.sql 按用户和会话过滤，取 seq > after_seq 的消息，按seq升序并限制条数。SQL参数通过驱动绑定，不拼接用户输入。
8. 仓储返回 [(seq, role, content), ...]，业务原样返回。路由逐条创建 HistoryMessageResponse，循环结束返回完整列表；FastAPI/Pydantic 最终输出 JSON 数组。空历史是[]，序号和正文保持数据库原值。
9. SessionNotFoundError 是 ValueError 的子类，因此先捕获并转为404，再处理一般ValueError为400；MySQLError为503，其他未预期异常由全局中间件处理为500。失败记录安全日志；数据库和意外错误只向客户端提示“请稍后重试。”。

这条接口只供页面查看历史，不调用模型。发送或重试时仍由 ChatService 重新读取服务端上下文。

## 新的 Query 是什么

Query 来自 FastAPI，用于声明 URL 查询参数的默认值、范围和文档。例如：

```text
/sessions/会话UUID/messages?after_seq=2&limit=20
```

session_id 来自路径，after_seq、limit 来自问号后的查询参数。

- after_seq 默认0，ge=0 表示不小于0，le=2**64-1 表示不超过数据库序号范围。
- limit 默认50，ge=1、le=100 表示每页1～100条。
- 类型或范围不合法时，FastAPI 返回安全的422，不执行历史业务方法。

仓储仍保留校验，以保护来自其他调用入口的请求。合法 UUID 的实际会话存在性和归属继续由仓储检查；缺失或不属于用户时统一404。

## 文件与包的职责

| 对象 | 来源 | 作用 |
| --- | --- | --- |
| logging | Python 标准库 | 获取本文件日志对象和告警级别 |
| APIRouter | FastAPI | 声明 /sessions 前缀和历史路径 |
| Query | FastAPI | 声明并校验分页查询参数 |
| Depends | FastAPI | 注入用户身份与历史服务 |
| HTTPException | FastAPI | 转换已知业务错误为HTTP响应 |
| Response | FastAPI 导出 | 设置不缓存响应头 |
| MySQLError | 第三方 MySQL 驱动 | 识别数据库异常并返回通用503 |
| require_current_user | 项目身份依赖 | 通过 Token 确认当前用户 |
| get_chat_history_service | 项目工厂 | 提供已经组装的历史服务对象 |
| HistoryMessageResponse | 项目数据模型 | 声明一条消息的seq、role、content |
| UserResponse | 项目数据模型 | 承载已确认的用户身份 |
| SessionNotFoundError | 项目异常模块 | 区分404；先于其父类ValueError处理 |
| log_failure | 项目日志模块 | 记录安全的失败信息，不记录聊天正文 |
| ChatHistoryService | 项目业务模块 | 在工作线程中查询一页消息 |

本次路由不导入模型网关，不保存消息，不生成模型回复。业务模块负责调度读取，仓储负责SQL与归属检查，main.py负责最终注册路由。

## 写完后的验收用例

| 场景 | 预期 |
| --- | --- |
| 自己有消息的会话 | 200，返回seq、role、content |
| 自己的空会话或游标到末尾 | 200，返回 [] |
| after_seq=1、limit=1 | 只返回下一条消息，保留数据库原序号 |
| 缺少、无效或已撤销 Token | 401 |
| 别人的会话、不存在或已删除的会话 | 相同404提示 |
| UUID 格式不合法 | 400 |
| limit=0、limit=101、after_seq=-1或分页参数不是整数 | 422 |
| URL额外传 user_id | 当前身份仍来自Token，不能读取他人数据 |
| 数据库异常 | 503，只提示“请稍后重试。” |
| 其他未预期错误 | 全局通用500并记录日志 |
| 查看历史 | 不触发模型、不创建问题或回复 |

以上场景已有模拟接口测试；真实临时库验证了本文件开头列出的真实链路。你可以继续在 /docs 用自己的会话手工验收：先登录并 Authorize，再填写会话UUID及分页参数。尚未验证真实 Uvicorn 网络访问或前端点击行为。

# 历史展示与模型上下文的读取时机

## 点击会话时

前端将来点击某个会话后，调用 GET /sessions/{session_id}/messages，读取一页历史显示在页面上。可以默认50条，继续翻页时带 after_seq。

这个请求只做身份与归属检查、查询数据库和返回消息。它不调用模型，不把消息送入模型输入，也不创建新一轮问题。模型不会因为用户点击会话就预先记住这些消息。

## 发送问题时

后续发送接口把当前登录用户 ID、会话 ID和新问题交给 ChatService.send_message。

```text
先保存本轮问题
  → claim_turn 检查归属并领取生成任务
  → 从数据库读取本轮需要的历史，其中已包含新问题
  → 组装 system 消息与会话消息
  → ModelGateway.invoke 调用模型
  → 保存模型回复
```

现有 ChatService 已采用这条路径。重试也会重新领取任务并读取历史，不重复保存一条“继续”。

页面只加载了两条历史时，服务端仍按数据库当前状态组装模型上下文；不能直接拿浏览器分页列表当成可信的完整上下文。其他设备新增的消息也应以服务端记录为准。

本阶段沿用现有模型历史组装方式；上下文裁剪和摘要压缩属于后续上下文管理阶段。它们同样在发送或重试时执行，不由查看历史接口触发。

## 当前实现与验证

| 模块 | 作用 | 会调用模型吗 |
| --- | --- | --- |
| ChatHistoryService | 分页读取供页面展示的历史 | 不会 |
| MessageRepository.load_history_page | 按权限、游标、数量查询展示数据 | 不会 |
| ChatService.send_message / retry_message | 组织提问、读取上下文、生成并保存回复 | 正常生成路径会调用 |
| ModelGateway.invoke | 实际发起模型请求 | 会 |

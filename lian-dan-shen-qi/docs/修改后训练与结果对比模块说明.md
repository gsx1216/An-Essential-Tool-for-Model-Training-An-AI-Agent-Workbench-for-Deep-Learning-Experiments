本阶段接通“原运行 → 有依据的修改 → 独立代码副本 → 新运行 → 报告对比”。**准备新运行不会启动训练**，启动需要独立的 API 操作或当前聊天中明确的训练指令。没有调用真实模型或运行真实 GPU 训练来做本阶段验收。

## 1. 整体流程

```mermaid
flowchart TD
    U[用户选择已应用的 change_id] --> AUTH[Token 确认当前用户]
    AUTH --> OWN[确认修改、原运行、服务器归属]
    OWN --> CHECK[检查没有失败项\n确认部署者登记的副本入口模式]
    CHECK --> SSH[固定 SSH 辅助程序只读预检\n核对已修改文件和登记入口\n计算整个副本的文件清单及 SHA256]
    SSH --> SAVE[一个 MySQL 事务\n创建 created 新运行\n复制原参数及评测快照\n保存原运行/修改/新运行关系]
    SAVE --> WAIT[返回新 run_id；尚未训练]
    WAIT --> START[用户明确启动该新运行]
    START --> BIND[复用 Runner 原子执行绑定\n同时登记监控任务]
    BIND --> FREEZE[监督器再次核对完整源码清单\n拷贝到本运行 revision_source]
    FREEZE -->|版本符合| TRAIN[执行修改后的源码\n复用已登记输入与环境]
    FREEZE -->|文件缺失/增加/变化| FAIL[明确失败；不启动训练]
    TRAIN --> MON[原有监控 Worker\n状态/日志/结构化指标/终态报告]
    MON --> COMP[用户查询对比接口或聊天工具]
    COMP --> READY{报告完整、当前且声明匹配?}
    READY -->|是| ROWS[按数据集/split/指标/最后 step 对比]
    READY -->|否| WHY[给出缺失或不可比原因；不补造数值]
```

“准备”和“启动”分开，是因为预检成功、计划已保存、已提交启动、训练完成是不同状态。SSH 启动响应丢失后只查询或重试同一个 run；不会为重试分配另一个训练任务。

## 2. 各模块具体做什么

| 模块 | 职责 |
| --- | --- |
| `app/api/revision_run_routes.py` | 5 个受保护接口：准备、列表、详情、启动、对比。只接收 ID 和参数，不接收命令、密码、源码路径或 user_id。 |
| `app/models/revision_run.py` | 请求/响应结构、部署模式校验、当前人类启动指令判断、报告比较算法。 |
| `app/repositories/revision_run_repository.py` | 用参数化 SQL 读写关系，验证归属/摘要；一个事务同时创建新运行、评测副本和关联记录；聊天单轮领取。 |
| `app/services/revision_run_service.py` | 串联修改记录、原运行、预检、保存、启动和报告。它不请求模型生成命令，也不另写一套训练执行器。 |
| `app/services/revision_transport.py` | 复用 SSH 连接器和固定 bootstrap，配置经 stdin 传输，校验预检返回的文件路径、SHA、模式和 PRNet profile。 |
| `app/runner/revision_source.py` | Linux 上只读检查候选目录；启动时核对整个清单并复制本次执行源码；为已审核的 PRNet 模板生成本次入口。 |
| `app/models/revision_tools.py` | 5 个聊天工具参数与描述，区分只读和启动工具，限制模型能够提供的字段。 |
| `app/services/chat_revision_service.py` | 将当前聊天调用适配成上述业务方法；request_id 由后端根据当前会话/轮次生成，不由模型提供。 |
| `app/services/runner_service.py` | 原 `/runs/{id}/start` 也读取 revision 绑定；不能通过旧接口绕过候选源码设置。 |
| `app/runner/remote_agent.py` | 沿用原监督进程和 job 锁；执行前固定源码，执行后沿用产物发布。 |
| `app/runner/prnet_adapter.py` | 默认运行行为保持原样；在修改后训练时，从本次固定源码取训练文件，从原项目取数据/预训练权重。 |
| `app/services/source_code_service.py` | 新运行的代码接口读取它自己的固定源码；不会回到原始项目读取旧代码来分析新结果。 |
| 现有监控、指标、分析、建议模块 | 新 run 仍进入原有链路；本阶段没有复制 Worker、另建 Redis 队列或新模型网关。 |

服务层负责流程，仓储层负责数据库事务。`asyncio.to_thread(...)` 把现有同步 MySQL 调用放在线程执行，`await` 等待该结果期间事件循环可处理其他请求；SSH 调用本身使用异步连接器。

## 3. 技术栈和包

| 技术/包 | 本阶段用途 |
| --- | --- |
| FastAPI | HTTP 路由、依赖注入、Swagger。`Depends(require_current_user)` 先验证登录，再把当前用户交给业务方法。 |
| Pydantic | UUID、请求字段、参数及返回结构校验；禁止额外传入 user_id、shell 等字段。 |
| mysql-connector-python / MySQL InnoDB | 参数化 SQL、短事务、行锁、归属复合外键、请求唯一键。 |
| AsyncSSH（现有连接器） | 使用已有 IP 允许范围、主机指纹和个人加密凭据建立连接。没有新增免校验 SSH 通道。 |
| asyncio | SSH 异步等待、操作超时、同步数据库转线程。 |
| pathlib、hashlib、json、ast、os、stat | 路径、文件清单/SHA256、固定协议、静态提取 PRNet 的字面量配置、普通文件/链接检查。预检不导入用户项目。 |
| subprocess（现有 Runner） | 监督进程执行固定 argv，继续管理停止、超时、日志和退出码。 |
| Redis（沿用） | 上下文缓存以及报告事件通信继续使用已有 Redis；训练执行绑定和 revision 关系以 MySQL 为准。 |
| PyTorch | 只有用户真正启动 PRNet 时，其既有训练环境才加载它。验收没有加载真实模型做训练。 |

没有新增第三方依赖。

## 4. 身份、会话和启动授权

1. `require_current_user` 从 Bearer Token 找有效登录记录，检查有效期并取得当前用户；请求体中的身份字段不能覆盖它。
2. 修改仓储确认 change_id 属于本人；运行、服务器也按本人范围查询，越权返回 404。
3. 准备时检查修改已应用、没有失败检查、原运行已结束并有评测声明、入口仍是登记版本、服务器绑定未变化。
4. SSH 凭据临时解密，用完在 `finally` 中清空字典，不进入运行参数或源码清单。
5. HTTP 的专用启动 POST 本身就是用户执行操作。聊天工具则额外从 MySQL 读取**本轮原始人类消息**，验证当前生成尝试和明确的 change_id/run_id 启动指令；论文、工具返回、旧摘要不能授权启动。
6. 聊天在会话锁内记录单轮领取；普通训练与修改后训练相互检查领取记录，不能一轮启动两个运行。候选启动模式不同时提供代码应用、普通训练启动和联网研究工具。

聊天中的 `request_id` 是创建新计划的幂等编号；新训练有新编号，重试同一轮保持原编号。API 客户端也应在点击一次“准备训练”时生成一个 UUID，并在该操作重试时复用；不用让最终用户手抄 ID。

## 5. 数据库新增两张表

### revision_runs

| 字段 | 保存内容 |
| --- | --- |
| run_id / user_id | 新运行及其归属，关联现有 experiment_runs。 |
| original_run_id | 作为基线的原运行，保留原日志和报告。 |
| change_id | 来源修改记录，保留建议、diff 和检查历史。 |
| request_id | 当前用户创建候选运行的幂等键。 |
| binding_json / binding_digest | 冻结目标、参数覆盖、源码清单/SHA、模式、检查状态及固定辅助程序版本；读回校验摘要。不是密码存储位置。 |
| origin_session_id | 创建来源聊天，仅做来源记录；删除聊天不会删除运行。 |
| created_at | 创建时间。 |

新运行、原运行和修改通过归属外键关联。为已有 code_changes 增加 `(id,user_id)` 唯一索引，支撑修改归属复合外键。

### revision_launch_claims

保存 `(session_id,turn_id,user_id,run_id)`，主键 `(session_id,turn_id)`，用于限制当前人类一轮提问只能启动一份新训练。删除聊天会清除此临时授权关联，持久的 revision_runs、运行和报告仍保留。

新运行记录、参数、评测、执行绑定、监控任务、指标、报告和事件继续存在原来的共享表，不为每个用户创建新表。当前共 **36 张共享业务表**。

## 6. 源码、数据、权重和 Python 如何分开

准备时保存全部候选文件的路径/SHA，限 512 个源码文件、20 MiB；文件本身最多 1 MiB。完整序列化启动快照还受执行器约 128 KiB 预算约束，超过时在保存计划前明确拒绝。检测隐藏文件、链接、特殊文件和非源码类型，不把原始数据/权重当源码复制。候选里缺少部署所需源码时不能声称已具备完整训练环境。

用户点击启动后，Runner 再核对同一份完整清单，复制到：

```text
原项目/.experiment-assistant/<job_id>/revision_source/
```

后续编辑 `code_changes/<change_id>/project` 不影响已经固定的执行源码。这是每个运行自己的源码拷贝，不是操作系统只读沙箱；如果有人直接改动该拷贝，代码接口的 `frozen_source_match` 可以显示不一致。运行结束后的可见产物仍发布到：

```text
原项目/<原运行冻结的 output_directory>/<新 run_id>/
    run.json
    output.log
    artifacts/
        last.pth              # PRNet 正常完成时
        metrics.jsonl
        provenance.json
        result.json
```

训练状态与产物发布状态分别展示，具体文件以真实 `observation.outputs` 和目录内容为准。API 返回 `output_directory` 是预定位置，不代表权重已经生成。

部署者在 `config/revision_scripts.json` 按已登记 script_id 确认模式；本机现有 `prnet_train` 已配置为 `prnet`，不修改其原始登记入口：

- **prnet**：只接受审核过的新/旧 PRNet 适配器模板，静态读取 DEPLOYMENT，不执行它来取得配置。训练源码从固定副本取，数据、预训练权重、GPU 锁和既有 Python 从原部署取。支持修改现有 SOURCE_FILES 六个文件；改适配器、添加未集成的依赖或改变输入布局，需要部署者更新适配器，不由模型自动猜测。
- **cwd**：用于部署者确认支持副本运行的通用入口。运行目录和 PYTHONPATH 指向固定源码，使用原 Runner 的 Python；额外提供 `EXPERIMENT_SOURCE_ROOT`、`EXPERIMENT_INPUT_ROOT`、`EXPERIMENT_ARTIFACT_DIR`。项目入口需正确使用这些输入/输出约定；写死原绝对源码路径的任意脚本，不能仅靠切换 cwd 就保证会执行新代码，因此没有自动为所有脚本开启此模式。

PRNet 六个源码路径：`PRNet_train_cod.py`、`options_cod.py`、`data_cod.py`、`utils.py`、`models/PRNet.py`、`models/smt.py`。适配器仍记录实际源文件、预训练权重 SHA 和数据文件名/大小清单；文件名/大小不等于数据内容完整哈希。

## 7. 结果怎样比较

比较接口只读 MySQL 中的保存报告，不连接 SSH、采集日志、生成报告或请求模型。

- 报告必须存在、是当前版本、采集完整，且对应成功运行；有质量警告时不生成数值结论。
- 原运行与新运行的完整评测声明必须相同，包括任务、协议/版本、数据集版本和指标定义。复制原运行的声明，不从可能已变化的当前实验定义重新获取。
- 用 `(dataset,split,metric_name)` 对齐；最后 step 不同、缺项、异常质量标记等单独说明，不拿 train 和 test 混比，不给缺失项补零。
- 比较 `last_value`，`delta=新值-原值`。minimize 时 delta<0 表示观测指标值更好；maximize 则相反；方向 none 不判断优劣。这里没有把各自最小值当作“最佳模型”。
- 参数变化另列 `parameter_changes`，报告版本也返回，方便追溯。

`comparable` 表示上述**保存声明和报告条件**满足，不证明数据文件内容、评测实际实现或随机过程完全相同。尤其修改数据加载或评测实现时，使用者需要审核并更新协议，不能只因声明未改就认定科学可比。单次指标变化也不证明代码修改带来因果改善。

## 8. 失败、恢复和当前范围

| 情况 | 行为 |
| --- | --- |
| 检查为 failed / 尚未应用 | 拒绝准备；先查看修改记录。 |
| 检查 incomplete | 可以准备，但返回此状态，不宣称所有测试通过。 |
| 同 request_id、同修改/参数 | 返回同一新 run，不再次预检或分配训练。 |
| 同 request_id 换目标或参数 | 409，不覆盖旧计划。 |
| 预检后候选文件增加、消失或变化 | Runner 在启动训练前记录 `REVISION_SOURCE_CHANGED`；旧 run 不自动重跑。 |
| 网络启动响应丢失 | 查询/重试同一个 run/job，使用原有幂等监督器；不能据错误分配第二次训练。 |
| 新运行未完成/报告未就绪 | 对比返回原因和空的数值结论，不报“训练已改善”。 |

本阶段从原始运行派生候选训练；不支持在派生运行内部继续嵌套生成下一层代码修改。可在原运行上创建另一份独立修改并训练、比较。动态 Skill、PDF/向量 RAG、前端和自动合并原项目均不在本阶段。

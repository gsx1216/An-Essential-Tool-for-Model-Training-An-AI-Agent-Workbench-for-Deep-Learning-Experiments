## 当前阶段：后端事件通信与后续 Agent 执行

聊天上下文 Redis 缓存已接入，完整原文和摘要仍及时持久化 MySQL。缓存命中保留轻量数据库校验并只取新增消息；过期、损坏或 Redis 失联时恢复原路径。未增加业务表或 HTTP 接口，整体进度不因一个缓存模块机械提高。详见 [缓存模块说明](Redis聊天上下文缓存模块与完整流程说明.md)、[启动与验证](Redis聊天缓存启动与接口验证说明.md)、[文件清单](Redis聊天缓存阶段文件变更清单.md)。

更新：独立分析 Worker 已从持久 queued 任务执行并保存版本结果，接收器仍只入队。默认管理员/本人双关闭，验证使用模拟模型。下一步是分析完成到论文研究的事件编排与独立有据建议 Agent，再推进 RAG、Skill、可审计代码修改、训练配置/产物接口与部署验收。前端按用户要求后置；整体百分比保留粗略范围，不按测试数量机械递增。详见 [分析模块](独立分析Agent执行与证据结果模块说明.md)、[接口与验证](独立分析Agent接口与Swagger验证说明.md)。

目标：用户发起训练后，不需要持续手动调用 refresh、metrics/sync 和生成报告接口。

```text
用户通过聊天 Tool 启动训练
    → 持久化运行与后台任务
    → Worker 按计划查询状态、增量采集指标
    → 运行完成/失败且采集到尾部后生成事实报告
    → 前端通过读取接口展示状态、曲线和报告
    → 完成或异常事件供后续分析 Agent 使用
```

实施顺序：

1. 已完成任务状态、领取、租约和恢复规则，以 MySQL 为事实来源。
2. 已完成有界 Worker，复用既有刷新、采集和报告服务。
3. 已接 Redis Streams，验证消费确认、重复消息、消费者中断、Redis 数据丢失后的补投递。
4. 已接分析任务执行器与独立证据上下文，模型验收使用模拟网关；正式后台分析需要管理员和本人明确启用。下一步接独立有据建议 Agent。
5. 已补 [后台监控接口与前端联调说明](后台监控接口与前端联调说明.md)，说明了读取、状态与轮询策略。

模型不需要每隔几秒读取日志。常规采集由普通程序完成，完成或异常时再触发 Agent 分析，减少模型调用。

已有命令和接口会保留可用路径。不要因为加入 Redis 就把持久聊天历史、训练事实和权限记录全部迁移到 Redis。

## 后端验收后开发第一版前端

按照用户本次要求，先推进后端及其验收，再启动前端页面；以下仅保留前端计划，不代表现在开始实现。

第一版页面范围：

1. 登录/注册。
2. 聊天主页面：会话列表、历史、发送、等待状态、重试、工具执行结果。
3. 设置：本人模型 Key、服务器配置与连接测试。
4. 训练任务目录：选择项目、默认参数和任务详情。
5. 运行详情：状态、有限日志、指标曲线、报告及停止操作。

前端语言/框架尚未确定，选型时再确认。先做“登录 → 配置 → 发出训练指令 → 查看结果”这条完整路径，暂不把论文库和多 Agent 配置面板塞进第一版。

当前聊天接口是一次请求返回完整 JSON，不具备已实现的 SSE/WebSocket 流式协议；前端不应假定已有逐 token 输出。实时推送、流式回答属于后续独立接口设计。

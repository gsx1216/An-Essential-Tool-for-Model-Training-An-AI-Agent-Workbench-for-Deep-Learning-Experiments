# 后台监控接口与前端联调说明

日期：2026-10-26。两个接口都已挂载至 app.main，并声明 MonitorResponse 响应模型。完整字段约束也可查 `/docs` 或仓库 OpenAPI。

## 1. 鉴权与边界

请求头：`Authorization: Bearer <登录接口返回的 access_token>`。用户身份由后端确定，不接收 user_id。

run_id 是路径中的 UUID 字符串；传 UUID 的标准连字符格式或现有 32 位格式，由路由规范化。下面的 `<run_id>` 是占位符，必须换成本人的实际运行 ID。

读取和重新排队都不直接连接 SSH、不调用模型、不重新训练。Worker 是独立进程，必须运行后才会消费已排队任务。

## 2. GET /runs/{run_id}/monitor

用途：读取本人运行的后台监控状态，适合前端轮询。

- path：run_id，必填 UUID。
- query：无。
- body：无。
- 成功：200；`Cache-Control: no-store`。

请求示例：

```http
GET /runs/<run_id>/monitor
Authorization: Bearer <access_token>
```

响应结构示例（时间和 ID 仅示意，不是可查询的验收记录）：

```json
{
  "run_id": "3fa85f6457174562b3fc2c963f66afa6",
  "status": "completed",
  "attempts": 3,
  "failure_count": 0,
  "next_poll_at": "2026-10-26T13:00:00Z",
  "last_attempt_at": "2026-10-26T12:59:59Z",
  "last_success_at": "2026-10-26T13:00:00Z",
  "last_error_code": null,
  "report_version": 1,
  "lease_active": false,
  "updated_at": "2026-10-26T13:00:00Z",
  "completed_at": "2026-10-26T13:00:00Z"
}
```

字段说明：

| 字段 | 类型 / 可空 | 含义 |
| --- | --- | --- |
| run_id | string | 原训练运行，不是新建的重试运行 |
| status | enum | scheduled / running / completed / attention，属于监控状态 |
| attempts | integer | 总领取次数，含因过期恢复的再次领取 |
| failure_count | integer | 连续错误次数，成功观测后清零 |
| next_poll_at | datetime | scheduled 时下一次到期时间；终态时不能据此判断有待执行任务 |
| last_attempt_at | datetime / null | 最近领取时间；尚未领取为 null |
| last_success_at | datetime / null | 最近成功处理时间，不代表训练成功时间 |
| last_error_code | string / null | 固定安全分类，不包含驱动原始异常或凭据 |
| report_version | integer / null | 监控最近生成 / 复用的报告版本 |
| lease_active | boolean | 此时数据库租约是否有效；不证明操作系统进程一定存活 |
| updated_at | datetime | 最近任务状态更新 |
| completed_at | datetime / null | 完整报告完成时刻；attention 不伪装完成 |

时间按 UTC 返回，前端按用户时区展示。接口不暴露 lease_token、user_id、SSH 凭据或启动快照。

## 3. POST /runs/{run_id}/monitor/retry

用途：重新排队原运行的状态采集和报告任务。可恢复 attention，也可显式为历史终态执行登记监控，或复核已完成报告。**不是训练 retry / restart 接口。**

- path：run_id，必填 UUID，必须已有本人执行绑定。
- query：无。
- body：无，不需要发送 `{}`，也不接收新参数、服务器或脚本。
- 成功：202，响应与 GET 共用 MonitorResponse，通常状态为 scheduled。
- 有仍有效的 running 租约：409，避免抢占当前 Worker。

```http
POST /runs/<run_id>/monitor/retry
Authorization: Bearer <access_token>
```

成功响应中原 run_id 不变，failure_count 清零、last_error_code 清空、next_poll_at 为当前到期时间。总 attempts 不清零，已有 report_version 可以保留，不能当作重试后立刻已生成新报告。

重复请求不会创建多行监控或第二场训练；如果期间 Worker 已领取，后续请求可返回 409。202 只表示排队，不代表报告已重建。无需请求 request_id，去重目标是路径中的原 run_id。

## 4. 错误码与示例

| HTTP | 含义 | 前端动作 |
| --- | --- | --- |
| 401 | 登录无效、缺 Token 或已过期 | 重新登录 |
| 404 | 运行 / 执行 / 监控不存在，或不属于当前用户 | 提示不可访问；未启动的 run 不能凭此接口开始训练 |
| 409 | retry 时仍有有效 Worker 租约 | 等待后读取状态，不新建训练 |
| 422 | run_id 不是有效 UUID | 修正前端传参 |
| 503 | 数据库 / 持久协议等暂不可用 | 使用原 run_id 稍后查询，记录请求关联信息 |

不存在或越权：

```json
{"detail":"监控任务或运行不存在或不可访问。"}
```

运行中冲突：

```json
{"detail":"监控任务正在处理，请稍后重试。"}
```

暂不可用：

```json
{"detail":"请稍后重试。"}
```

UUID 错误通过现有请求校验处理器返回安全字段信息，例如：

```json
{"detail":[{"loc":["path","run_id"],"type":"uuid_parsing","msg":"请求字段缺失或格式不正确。"}]}
```

## 5. last_error_code 怎么理解

| 类别 | 值 | 处理 |
| --- | --- | --- |
| 暂时性问题 | SOURCE_UNAVAILABLE、CONNECTION_ERROR、TIMEOUT、SYNC_CONFLICT、STORAGE_ERROR、INTERNAL_ERROR | 自动退避，达到上限后 attention |
| 配置 / 身份问题 | AUTHENTICATION_FAILED、HOST_KEY_MISMATCH、ADDRESS_NOT_ALLOWED、CREDENTIALS_UNAVAILABLE、CONFIGURATION_CHANGED、PROTOCOL_ERROR | 立即 attention，先核对配置，再明确重排 |
| 日志来源变化 | SOURCE_CHANGED | 保留已有指标，不自动清空游标或伪造数据 |
| 日志截断 | LOG_TRUNCATED | 已存不完整报告，展示警告，不声称采集完整 |
| Worker 取消 | WORKER_CANCELLED | 当前任务尽量重新排队，后续恢复；不代表训练取消 |

未确认观测按 SOURCE_UNAVAILABLE 处理。错误码不直接决定训练状态，训练状态应读取 execution 或报告中的 status。

## 6. 前端调用顺序

1. 聊天发送明确训练指令，继续使用已有消息 request_id / 重试约定。
2. 读取当前聊天计划或运行列表，得到真实 run_id，不靠解析模型回复文字推算。
3. 轮询 `GET /runs/{run_id}/monitor` 和 `GET /runs/{run_id}/execution`；页面指标从 metrics / metrics/latest 读取。
4. Worker 到期后会自动推进，无需浏览器反复 POST refresh / sync / report。
5. monitor.completed 后读取 GET report，仍展示 report.version、is_stale、collection_complete；训练 failed 时如实显示失败报告。
6. attention 显示原因及已有事实，用户处理后可选择“重试监控”；不把按钮命名为“重新训练”。

开发时可按 3～5 秒轮询起步，并在页面离开后停止轮询；这是前端策略，不是服务端推送承诺。当前没有新增 SSE / WebSocket。Worker 未启动时 scheduled 会持续等待，重试按钮不能替代启动 Worker 进程。

前端最少状态文案：等待监控、正在采集、采集完成、需要处理；另外独立显示训练的排队、运行、成功、失败或取消状态。

模块和恢复机制见 [后台训练监控Worker与恢复机制说明](后台训练监控Worker与恢复机制说明.md)。

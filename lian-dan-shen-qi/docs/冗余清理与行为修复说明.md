# 冗余清理与行为修复说明

日期：2026-10-28。

本次完成上轮审查确认的 7 项修复。沿用已有 Python、FastAPI、MySQL、Redis、logging、unittest 和 httpx，没有新增依赖、业务表、HTTP 接口或后台进程。Redis 上下文缓存仍为 7 天。训练去重、用户归属、数据库事务、任务租约和论文引用核验继续保留。

## 1. 日志恢复必要的排查信息

旧流程用 logger.info("…%s…", value) 传递缓存命中、错误类型、事件 ID 等信息，但安全格式器不读取 record.args，导致这些内容被丢弃。

现在缓存、上下文数据库核对、Redis 事件投递均使用固定事件名与 extra 字段。logging_config.py 只接收有类型/格式限制的字段，例如 session_id、event_id、run_id、Redis message_id、cache_mode、delivery_status、state_saved。文本和 JSON 格式都能显示这些字段。正文、密码、Token、Key、任意消息参数和原始异常正文仍不会自动进入日志。

事件名称只在已有事件字典中定义一次，避免标签表和允许列表重复维护。

## 2. 已保存回复不依赖个人模型 Key

HTTP 聊天流程为：

```text
require_current_user：校验登录 Token，取得服务端 user_id
    ↓
UserChatService.send_message：校验输入
    ↓ 有 request_id
MessageRepository.find_request_reply：一条只读 SQL
    ├─ 会话不属于本人或已删除 → 404
    ├─ 编号已存在，但原问题不同 → 409
    ├─ 同一原问题且已完成 → 直接返回已保存回复
    └─ 新请求或尚未完成 → 继续原生成流程
          ↓
读取本人 Key → 构造网关 → start_turn → claim_turn
          ↓
准备上下文 → 调用模型 → 保存回复 → 关闭网关
```

当前 request_id 就是该会话轮次的 ID。SQL 通过会话表限制 user_id，并关联原问题与回复；原问题在 Python 中精确比较，避免受数据库大小写排序规则影响。

这增加了一条按主键关联的只读快查，保留“新问题缺少 Key 时不写入消息”的现有行为。快查不承担写入并发控制；实际新建、领取和完成仍由原事务与唯一约束处理。快查之后另一请求完成时，ChatService 原有已完成分支仍会返回原回复。

不带 request_id 的内部兼容调用沿用原流程。`/retry` 仍用于等待回复的问题，需要可用 Key；它不是已完成回复的读取接口。部署级加密主密钥仍需正常配置。

## 3. 工具预算按当前输入额度分配

以前所有工具输出合计写死为 4,500 字节，每次最多 2,600 字节。

现在总预算为 `min(完整输入预算 // 3, 16384)`，单次返回最多 8,192 字节；每次还受剩余真实请求空间限制。48K 应用输入预算对应最多 16 KiB 工具结果，并不保证每次都有全部空间，历史、工具定义和提示词同样占用输入。

本项目当前按 UTF-8 字节和封装余量估算输入，不是供应商精确 tokenizer，`*_tokens` 配置名称沿用现有接口。

普通读取剩余不足 512 字节时不再执行查询；准备/启动训练仍要求至少 1,800 字节结果空间。剩余空间不足时要求模型结束工具调用；模型仍请求工具时也不会越过服务端检查。连固定失败结果都容纳不下时返回预算错误，不再返回比允许空间更大的结果。

仍保留 4/6 次调用上限、参数校验、单次超时、归属检查和逐次工具审计。

## 4. 一次历史校验，内部复用

ContextManager.prepare 保留一次完整的类型、序号、角色、内容和摘要边界校验。内部组装消息与查找缺口复用已校验的数据和缺口结果，不再对同一份历史重复校验 3 次。

公开的 find_history_gaps、build_history_messages 仍独立校验输入。摘要和精简后的新输出仍会检查长度、格式及实际输入占用。独立练习调用切分方法时，仍保留必要的输入边界提示。

## 5. 简化会话读取

SessionRepository.list_sessions 和 get_session 直接执行带 user_id 的查询，不再先查一次 users。不存在的用户没有所属记录，结果分别为 [] 和 None；HTTP 登录校验仍由 require_current_user 完成。

创建会话仍保留已有用户检查、外键和回滚；删除仍锁定本人会话并在事务中删除消息/轮次。不能把此调整扩大为删除所有归属检查。

## 6. 删除没有消费方的结果哈希

不再新增工具审计 metadata.result_sha256，也不再为了这一字段导入 hashlib。工具名称、参数、返回分类、结果大小、耗时、运行绑定、报告版本和质量标记仍会保存。

旧审计记录不修改，已有 result_sha256 字段仍可随旧记录原样返回。脚本版本、训练配置、报告来源、请求去重和登录 Token 存储实际使用的哈希继续保留。

## 7. 整理遗留练习

早期 JSON 仓储移到 examples/json_chat_repository.py，保留学习代码。删除空的 change_service.py 和 orchestrator.py；它们原本没有实现或调用者，不代表删除已有 Agent、Worker 或训练功能。

# 服务器资源发现、通用训练配置、服务器删除与聊天标题

日期：2026-10-29。前端位于 `C:\Users\gsx\Desktop\炼丹神器前端`，后端位于 `E:\code\LangChian_New`。

## 用户现在如何配置训练

1. 在“训练服务器”添加自己的 SSH 连接，工作目录填写实际项目根目录。
2. 在“实验与训练”创建 training 类型的实验，评测方向与指标由实验定义描述。
3. 打开“配置对话训练任务”，填写名称并选择实验和服务器。
4. 默认选择“选择我的项目”。系统读取该服务器的 Python 环境和项目文件，无需部署者先在全局配置登记脚本。
5. 选择实际 Python 路径，例如 `/mnt/Data/HOME/gsx/miniconda3/envs/mynet/bin/python`。
6. 在文件列表中进入目录，选择实际 `.py` 训练入口，例如 `PRNet_train_cod.py`。
7. 按训练脚本要求填写启动参数；可添加允许在聊天中调整的参数，并勾选 GPU。
8. 保存配置。此时不会执行训练。之后在聊天中明确说“启动我的 PRNet 训练”，由 Agent 调用已有训练工具执行。

原有“已登记脚本”保留为可选的快捷模板。普通用户自己的项目不再依赖部署者修改 `runner_scripts.json`。

### 环境发现的实际范围

系统检查 SSH 用户 PATH 中的 Python、`~/.conda/environments.txt` 登记的环境、用户主目录和 `/opt` 下的常见 Conda 安装，以及项目 `.venv`、`venv`、`env`。

只返回存在且可执行的 Python 文件，不运行每个候选解释器、不激活环境、不安装依赖、不导入用户项目。这里的“可用环境”指解释器入口可执行，不保证已经安装 PyTorch、CUDA 或项目所需的全部包。

使用绝对 Python 路径即可使用该环境的包，不需要把 `conda activate` 写进启动参数。未自动发现的环境可以在选择框输入绝对 Python 路径。

发现最多返回 32 个环境，超过时明确提示结果不完整。不会遍历整块服务器磁盘。文件浏览也限定在该服务器配置的工作目录内，沿用已有的敏感文件、输出目录和路径边界规则。

### 参数如何填写

“额外启动参数”每行是一个独立 argv 参数，例如脚本支持 `--data` 和 `--output` 时：

```text
--data
/mnt/datasets/COD10K
--output
{artifact_dir}
```

不用填写 `python` 或 `train.py`，也不能填写 shell 管道、环境激活、`&&` 等命令。系统按参数列表传递，不使用 shell 解释它们。`{artifact_dir}` 是每次运行独立的产物目录，只有脚本接受对应参数时才填写。

希望之后在聊天中调整 epochs 时，可以添加一行：

| 参数名称 | 脚本选项 | 类型 | 默认值 |
| --- | --- | --- | --- |
| epochs | --epochs | 整数 | 100 |
| learning_rate | --lr | 小数 | 0.0001 |

系统生成 `--epochs {epochs}`、`--lr {learning_rate}` 的参数模板，并保存类型和默认值。脚本选项必须按实际 argparse 或项目文档填写，系统不会猜测所有项目都使用相同参数名。

当前页面默认单次运行上限为 24 小时，日志上限为 10 MiB，沿用后端默认值。更复杂的指标正则规则仍由 ProjectLaunch 接口支持，本次页面没有自动推测日志指标定义。任务类型、训练入口和评测指标是不同概念。

## GPU 资源如何显示

服务器卡片加载后，会通过 SSH 执行固定只读查询：

```bash
nvidia-smi --query-gpu=index,name,memory.total,memory.used,utilization.gpu --format=csv,noheader,nounits
```

页面显示检测到的 GPU 数量、编号、型号、总显存、已用/剩余显存和利用率。训练配置复用同一个面板，勾选后保存为 `cuda_visible_devices`，例如 `0,2`。没有勾选时继承远端环境。

这些是读取时的快照；点击“刷新 GPU”重新查询。GPU 正在被占用不一定完全不能使用，空闲显存也不保证足够运行某个模型，所以页面不把“检测到”直接宣称成“保证能启动训练”。

没有 nvidia-smi 时显示未发现工具；查询超时或驱动问题显示当前无法读取，不把失败伪造成 0 张可用卡。查询使用固定参数，不接收用户提供的命令。

本次真实服务器读取结果：3 张 NVIDIA GeForce RTX 3060，每张 12288 MiB。读取时显存占用为 8、48、8 MiB，利用率均为 0%。这是验证时的状态，后续以刷新结果为准。

## 为什么原来删除服务器会失败

实际日志返回 409，MySQL 错误号 1451。服务器表被 `training_tasks`、`run_executions` 外键引用，直接物理删除会破坏历史关联。这个问题不是删除按钮没接上。

按照用户选择，现在删除的语义是：

- 清空这条配置的 `encrypted_credentials`，不再保留可恢复的连接密文。
- 设置 `deleted_at`，从服务器列表中移除；后续详情和 SSH 读取拒绝访问。
- 保留服务器 ID 等历史关联信息，因此原来的任务、运行和报告不会被级联删除。
- 不能再使用这条配置读取远端日志、源码或启动任务；原本关联它的任务需要重新配置。
- 服务器上的项目、数据和权重文件不会被删除。

如果仍存在排队中或运行中的训练，删除返回 409，先停止并同步运行状态后再删。删除操作先锁服务器记录，再检查活动执行；新执行绑定的 SQL 也会排除已删除服务器，避免并发启动绕过删除状态。

已增量迁移当前数据库。其他部署环境更新代码后运行：

```powershell
python -m app.database --server-schema
```

迁移添加 `deleted_at`，并修改密文检查约束：活动配置必须有合法长度的密文，已删除配置必须是空密文。迁移本身不会删除任何用户的服务器或清空现有凭据；实际清除只发生在用户确认删除时。

## 新聊天的标题

原先点击侧栏“新聊天”直接调用 `api.createSession()`，所以总使用后端默认“新聊天”。现在会先弹出输入框，用户填写 1～200 个字符的标题后，前端调用 `POST /sessions` 传入 title，后端继续按登录用户校验、生成 UUID 并持久保存。

取消输入不会创建会话。聊天工作台直接发送第一条问题时，仍沿用已有的“从问题截取标题后自动创建”行为。本次没有新增会话重命名接口。

```text

  → TrainingTaskService.project_source 校验服务器归属

  → 远端 source_reader.py 读取环境/目录，或固定查询 nvidia-smi

  → POST /training-tasks（project 配置）
  → 检查实验和服务器归属、参数规则
```

## 接口文档

资源发现接口都需要 `Authorization: Bearer ...`，客户端不能指定 user_id、SSH 密码或任意 shell 命令。服务器和工作目录由当前用户已有配置取得。

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `POST /training-projects/environments` | `{ "server_id": "UUID" }` | server_id、work_dir、items（name/python/kind）、truncated |
| `POST /training-projects/resources` | `{ "server_id": "UUID" }` | server_id、work_dir、gpu_status、gpus |
| `POST /training-projects/files`（复用） | server_id、path、offset、limit | 当前目录和分页文件列表 |
| `POST /training-projects/file`（复用） | server_id、path、start_line、line_count | 带行号的只读源码片段和文件 SHA256 |
| `POST /training-tasks`（复用通用分支） | name、experiment_id、server_id、project、default_parameters | 本人的任务配置；不开始训练 |
| `DELETE /servers/{id}`（修改语义） | 路径 ID | 204：凭据清空、列表移除；404：不可访问；409：存在活动执行 |
| `POST /sessions`（复用） | `{ "title": "我的论文讨论" }` | 服务端生成的 session_id |

GPU 结构示例：

```json
{
  "gpu_status": "available",
  "gpus": [{
    "index": 0,
    "name": "NVIDIA GeForce RTX 3060",
    "memory_total_mb": 12288,
    "memory_used_mb": 8,
    "utilization_percent": 0
  }]
}
```

GPU 状态为 available、not_installed 或 unavailable；利用率无法读出时为 null。完整字段契约已更新到后端 `/docs` 和桌面 `docs/api/openapi.json`，前端类型由 openapi-typescript 生成。

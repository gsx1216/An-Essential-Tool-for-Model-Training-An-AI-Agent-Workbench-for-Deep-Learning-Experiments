## 两种UUID分别是什么

session_id由新聊天接口生成，标识一段聊天，放在URL路径里。

request_id标识一个新的提问。客户端应在第一次发送前生成一次；同一问题因为网络超时而重新提交时，使用相同的request_id和内容。服务端借它识别“这是同一轮请求”，已完成时读取原回复，不重复保存问题或调用模型。

用户再次发送一个新问题时，生成新的request_id。后端如果每次收到请求都默认生成新UUID，就无法识别客户端的重发，所以这里要求调用方明确提交。它不是登录凭证，也不代替Token校验。

请求示意：

```json
{
  "content": "你好，请帮我分析训练日志",
  "request_id": "d5d2e70c-bd6b-40a0-9855-9066bc22a653"
}
```

这里的UUID只是格式示意。实际客户端每个新问题自行生成；调试工具也可以用本机uuid4生成。Pydantic把JSON字符串解析成UUID对象；传给现有业务时用request.request_id.hex取得32位字符串。hex是属性，不加括号。

这个请求去重ID和响应头X-Request-ID不同：前者在同一次逻辑提问的重发中保持不变，后者由日志中间件为每次HTTP请求生成，用于查日志。

## 一次请求如何执行

```text
将来挂载后的FastAPI路由
  → 解析正文、路径和Depends依赖
  → require_current_user验证Bearer Token并确定真实用户
  → get_user_chat_service提供组装好的业务对象
  → 路由await业务方法
  → 按用户读取个人Key，创建本次模型网关
  → 仓储确认会话归属，保存提问并读服务端新上下文
  → 调用模型，保存回复或失败状态，关闭网关
  → 成功时返回200和{"content":"已保存的回复"}
```

浏览器不能通过正文指定user_id、个人Key或整段历史来决定服务端的身份和上下文。页面之前加载了多少历史，不影响服务端本轮重新读取数据库。

历史接口GET /sessions/{session_id}/messages和新发送接口POST同一路径，HTTP方法不同，可以共存。重试单独使用POST /sessions/{session_id}/retry。

## 已提供的异常转换

两个接口在except KNOWN_CHAT_ERRORS中调用_raise_chat_http_error，转换规则已经由助手写好并验证，不需要你现在填写。

| 场景 | HTTP结果 |
| --- | --- |
| 无效或缺失登录Token | 身份依赖返回401 |
| 请求缺字段、UUID格式不合法或正文有额外字段 | 框架校验返回422，既有安全处理器不回显原始输入 |
| 会话不存在或不属于当前用户 | 404，统一提示 |
| 未配置个人Key | 400，提示先配置 |
| 供应商拒绝个人Key（401/403） | 400，提示检查个人模型配置；不把它误当成网站登录失败 |
| 业务参数不合要求 | 400，通用参数提示 |
| 数据库故障或已存凭据无法解密 | 503，“请稍后重试。” |
| 供应商请求限流 | 429，通用限流提示 |
| 供应商连接故障或其他SDK错误 | 502，通用模型服务提示 |
| 供应商响应超时 | 504，通用超时提示 |
| 未预期编程错误 | 既有请求中间件返回通用500并记录日志 |

不回传供应商的原始错误正文、数据库错误或请求头。原错误通过异常链和安全日志保留定位信息。

超时异常是连接异常的子类，因此助手提供的转换先判断超时。SessionNotFoundError和ModelCredentialNotConfiguredError继承ValueError，也必须在通用ValueError之前区分。

# 退出登录练习

当前注册、登录和 `/auth/me` 已接通。接下来让用户主动撤销当前 Token，使它在三天有效期结束前立即失效。

当前状态：LogoutService 的五个 TODO 已完成，Token 类型检查也已补齐。业务测试及真实临时 MySQL 验证通过后，继续按 `docs/退出登录接口接入练习.md` 完成工厂和路由。下文保留业务练习供回顾。

这次先填写 `app/services/logout_service.py` 中 `LogoutService.logout()` 的五个 TODO。构造函数、SQL、仓储事务和日志已经准备好。写完并检查通过后，再连接 `POST /auth/logout`。

## 要实现的调用顺序

```text
原始 access_token
  → 检查字符串类型和 43 位格式
  → 计算 token_hash
  → await asyncio.to_thread 调用 revoke_session
      → UPDATE 同时匹配哈希、未撤销、未过期
      → 写入 revoked_at，提交事务
  → 返回 True：业务正常完成，return None
  → 返回 False：抛出 InvalidTokenError
```

类型和格式判断可以参考你已写好的 `CurrentUserService.get_current_user()`。务必判断 `re.fullmatch()` 的结果，而不是只调用它。

## 已提供的方法

| 方法 | 输入 | 输出 | 调用方式 |
|---|---|---|---|
| `self.token_service.hash_token` | 原始 Token | Token 哈希 | 普通调用 |
| `self.session_repository.revoke_session` | Token 哈希 | bool | `await asyncio.to_thread(...)` |

`revoked=True` 表示数据库更新了一个有效凭证，并且提交成功；`False` 表示未知、已到期或已撤销。数据库故障会抛出异常，不会冒充 False。

## 数据库究竟改了什么

`sql/revoke_login_session.sql` 只把匹配记录的 `revoked_at` 设置为当前 UTC 时间。不会删除记录，不修改 `created_at`、`expires_at` 或用户表，也不撤销该用户的其他登录。

仓储执行一条带条件的 UPDATE，同时检查和修改状态，不需要你先调用 `get_current_user()` 再查询一遍。`token_hash` 有唯一约束，因此最多更新一条记录。

当前请求只提供自己的 Token，不接收 user_id、登录记录 ID 或其他用户的标识作为撤销目标。

## 为什么撤销后会失效

`/auth/me` 每次都通过 `get_active_login_user.sql` 查询数据库。该查询要求 `revoked_at IS NULL`。一旦撤销已提交，即使下次请求落在另一个 API 进程或 Pod，也会因同一份 MySQL 记录已经撤销而返回 401。

## 写完后验收

| 场景 | 应有结果 |
|---|---|
| 撤销当前有效 Token | 正常完成，返回 None |
| 再用它调用 `/auth/me` | 401 |
| 同一账号另一次登录的 Token | 仍有效 |
| 其他账号的 Token | 仍有效 |
| 再次撤销同一个 Token | InvalidTokenError |
| 格式错误、未知或到期的 Token | InvalidTokenError |
| 数据库故障 | 异常继续抛出，不能返回成功 |
| 撤销后的历史记录 | 保留，revoked_at 有时间，原有效期不变 |

当前业务层不需要 `HTTPException`，只使用业务异常。后续 HTTP 层会把无效凭证转换为 401，把数据库异常转换为 503；成功时计划返回 204，无响应正文。

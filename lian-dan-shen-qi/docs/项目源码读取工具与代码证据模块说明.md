# 项目源码读取工具与代码证据模块说明

更新日期：2026-10-28。

本阶段让聊天 Agent 按需列出训练项目文件、读取源码片段，并引用实际读取的文件、行号和文件版本。独立后台分析 Worker 仍读取训练报告；本阶段没有增加建议 Agent、自动修改源码或新的训练流程。

## 1. 已完成的流程

```text
用户：“检查最近训练的入口代码和损失函数”
  ↓ require_current_user：验证 Bearer Token，取得服务端当前用户
UserChatService：保存/领取当前问题，准备上下文
  ↓
ReadOnlyChatService：向模型提供已有查询工具及两个源码工具
  ├─ get_latest_training_run：查本人最近提交的训练，建立会话运行关联
  ├─ list_project_files：列目录，取得登记入口和可读文件
  └─ read_project_file：按行读取当前文件，按需分页
        ↓ SourceCodeService
        从本人运行的执行绑定取得服务器、启动快照和项目根目录
        ↓ 校验服务器绑定和 SSH 指纹，解密本人已保存的 SSH 凭据
        SourceTransport → SSH → 固定只读 Python 辅助程序
        ↓
        返回实际行号、完整行、文件版本和读取时间
  ↓
当前生成尝试仍有效时，将工具审计、代码证据及运行关联一起提交
  ↓
模型根据实际片段解释；后端附上真实读取范围
  ↓
最终回复保存到聊天历史，后续可通过工具审计查看代码依据
```

工具是模型可以请求后端执行的固定函数，不是允许模型执行任意 Python 或 shell。普通聊天虽然可以看到工具定义，但不会自动连接 SSH。

## 2. 两个工具

### list_project_files

参数：可选 run_id、path（默认 `.`）、offset（默认 0）、limit（默认 25，最多 50）。省略 run_id 时使用该会话已关联的本人运行；没有关联时需要先查询最近训练。

只列一个目录，不自动递归整个项目。返回 items、next_offset、entry_path、retrieved_at。entry_path 是运行启动时登记的脚本入口，可能是适配脚本；不能把适配脚本误当作整个模型实现。

### read_project_file

参数：可选 run_id、path（省略则读取登记入口）、start_line（默认 1）、line_count（默认 30，最多 60）、expected_sha256（可选）。

单个文件最多 1 MiB。每次返回完整行；行号和正文组成的 JSON 片段不超过 1,800 字节，以便完整保存到现有 4,096 字节工具审计字段中。因此实际返回可能少于 line_count，下一页必须使用 next_line，不能自行假设“起点 + 请求条数”。超长的单行明确报错，不截断后冒充完整行。

返回包含：

| 字段 | 含义 |
| --- | --- |
| path | 项目内相对路径 |
| lines | `[{number: 实际行号, text: 完整行正文}]` |
| start_line / end_line | 请求起点、实际返回终点；未返回行时 end_line 为 null |
| next_line | 后续读取起点；没有更多行时为 null |
| total_lines | 当前文件总物理行数 |
| file_sha256 | 本次读取的文件版本标识 |
| file_bytes / modified_ns | 文件大小与服务器文件修改时间 |
| retrieved_at | 后端完成读取的 UTC 时间 |
| version_scope | 固定 current_file，表示读取时的当前文件 |
| training_entry_match | 只有读取登记入口时比较启动记录：true 匹配、false 已变化；其他文件为 null |

SHA-256 在这里有两个具体消费者：后续分页的 expected_sha256，以及登记入口版本比较。它不是额外的无消费方校验文件，也不能证明整个项目或所有依赖与训练时相同。

同一轮对话里再次读取同一运行、同一路径时，后端会自动带上已读版本；跨轮次或直接调用 HTTP 接口时，调用方可显式提供 expected_sha256。文件已变化则拒绝混合分页。不同文件的读取不是整个项目的原子快照。

## 3. 代码证据保存在哪里

复用已有 MySQL 表 `chat_tool_calls`，没有新增业务表。成功且确实提供给模型的代码片段保存在 `result_meta_json.code_evidence`：

```json
{
  "citation_id": "code_1",
  "run_id": "本人运行的UUID",
  "path": "PRNet_train_cod.py",
  "file_sha256": "当前文件的64位版本标识",
  "retrieved_at": "2026-10-28T00:00:00Z",
  "start_line": 1,
  "end_line": 2,
  "lines": [
    {"number": 1, "text": "import torch"},
    {"number": 2, "text": "from models.PRNet import Network"}
  ],
  "version_scope": "current_file",
  "training_entry_match": null
}
```

上面是结构示例，不代表实际读取的 PRNet 内容。真实值由读取结果生成，模型不能提交自己的证据记录。citation_id 只在本轮对话有效。

只有审计提交成功后，片段才会提供给模型。数据库失败时不会继续把未记录的片段用于回答。审计仍校验会话归属、当前轮次、生成尝试与租约。文件之后变化不会覆盖之前保存的片段。

回复末尾由程序附上代码证据的路径、行号、版本和读取时间；模型使用 `[code_1]` 等编号时，会检查是否属于本轮已读片段。引用有效不代表模型解释、因果判断或修改方案已经被证明。

如果本轮请求读取源码但未取得任何代码片段，后端固定说明未取得源码，不接受模型“已经读完代码”的错误声称。仅列目录不会被当作已经读过源码。

通过 `GET /sessions/{session_id}/tool-calls` 查看本人会话证据。删除聊天时，相关工具审计和源码片段一起级联删除。训练运行和报告独立保留。直接调用源码 HTTP 查询接口返回实时结果，不归档到聊天审计，也不调用模型。

## 4. 读取边界

- 当前支持 Linux 服务器，辅助程序兼容 Python 3.8+，只使用标准库。
- 根目录来自本人运行的不可变启动绑定，不接收客户端或模型提供的根目录、SSH 身份、凭据或命令。
- 服务器当前绑定必须与启动记录一致；既有 SSH 网段策略、主机指纹校验、连接名额和超时继续生效。
- 项目内目录逐级通过文件描述符打开，禁止跟随符号链接；文件只读打开，不导入、编译或执行用户源码。
- 读取 `.py/.yaml/.yml/.json/.toml/.ini/.cfg/.md/.txt` 等 UTF-8 文本；拒绝隐藏路径、已知凭据文件、权重、输出目录、特殊文件和二进制。
- 名为 data/dataset/datasets 的目录下，Python 加载器可以读取，其余样本清单、标签和文本不作为源码返回。图片、数组、检查点等也不属于允许扩展名；这不是对任意自定义数据目录的语义识别。
- 扫描整份文件中的常见凭据模式再返回片段；发现模式时拒绝文件，不能只因为密钥在当前窗口之外就泄露后续窗口。模式过滤可能拒绝带有凭据字段名的配置，也不能保证识别所有自定义秘密。
- 单目录最多扫描 4,096 个条目。目录与文件超限时明确提示，不伪造完整清单或源码。
- 读取不启动/停止训练、不刷新训练观测、不修改源码或训练状态。源码/注释中的命令都只是资料。

## 5. 源码检查与训练工具的选择

原来的训练模式会被“训练”这个词触发。“检查训练代码”因此会误进入执行工具模式。本阶段在 training_mode 中识别代码检查问题，让这类问题进入只读模式。

“启动 PRNet”“有哪些训练任务”等既有行为仍保留。源码或论文读取与训练执行不混在同一轮工具循环；“先检查代码再启动”先完成只读检查，之后再明确要求启动。最终启动授权仍检查数据库中当前用户的原始指令，不能由源码或模型自行授权。

## 6. 每个模块与技术栈

| 文件 | 职责 | 技术 |
| --- | --- | --- |
| app/models/source_code.py | 工具参数、响应结构、实际代码证据与引用范围展示 | Pydantic、dataclasses |
| app/runner/source_reader.py | Linux 目录与文件的只读实现、完整行切片、凭据模式检查 | os.open/dir_fd/O_NOFOLLOW、stat、hashlib、json、re |
| app/services/source_transport.py | 固定 SSH bootstrap，参数通过 stdin 发送；校验返回路径、行号、游标和版本 | AsyncSSH、asyncio、Pydantic |
| app/services/source_code_service.py | 从本人执行记录取得服务器和根目录，核对绑定，释放凭据引用，标明版本范围 | 既有仓储、SSH 凭据加密器、asyncio.to_thread |
| app/api/source_code_routes.py | 两个鉴权查询接口及安全错误映射 | FastAPI、Depends、Query、HTTPException |
| app/api/dependencies.py | 复用 Runner 仓储、服务器服务和连接器，组装源码服务 | lru_cache、依赖注入 |
| app/services/read_only_chat_service.py | 模型按需调用、预算检查、同轮版本检查、审计后再提供代码、附读取依据 | 现有工具循环 |
| app/repositories/chat_tool_repository.py | 将源码工具纳入已有审计类型，沿用事务、归属与生成尝试校验 | mysql-connector、参数化 SQL |
| app/models/training_task.py | 避免把代码检查问题误路由到执行模式 | 原文关键字路由；不代替最终启动授权 |

没有新增依赖、Redis 队列或独立 Worker。Redis 继续负责既有聊天缓存和事件通信，源码读取本阶段按需直连 SSH，不缓存整份项目。

## 7. 验证

- 完整单元测试 1,182 项通过；其中本阶段源码专项 23 项，覆盖路径、参数、协议、分页、版本、归属、凭据释放、代码与论文证据组合及证据审计。
- 真实 HTTP/MySQL 验收 11 组：临时数据库、模拟模型和远端文件；验证无 Key 查询、越权、源码过滤、聊天取证、版本变化和聊天删除等。
- 真实 PRNet SSH 与 Linux 验收 11 组：已读取登记入口和 PRNet_train_cod.py，读取同版本后续页，拒绝旧版本；在 Linux 随机临时目录测试符号链接、凭据、文件大小、完整行分页、特殊文件等，临时目录已清理。
- 真实服务器 Python 版本为 3.8.10。测试未调用真实付费模型，未启动训练，未修改 PRNet 项目源码和权重。

真实模型是否正确选择文件、是否准确理解代码，仍需要用户在自己的聊天接口中验证；这里的自动化验证使用模拟模型，不把它当成真实模型质量评测。

## 这一步要完成什么

个人Key管理接口已经由你确认可用。下一步把“Key已安全保存”与“聊天调用使用本人的Key”连起来。先完成一个小工厂，接收用户ID并返回用该用户Key创建的新ModelGateway；写完检查通过后，再接入聊天业务和HTTP接口。

当前练习文件：`app/services/user_model_gateway_factory.py`。类名是 `UserModelGatewayFactory`，本次只填 `create_for_user` 中4个TODO。构造函数、日志装饰器和测试已经准备好。

工厂的意思是“负责创建对象”。这里需要先异步查询并解密个人Key，再用它创建网关，因此把这段组装逻辑集中在一个类里。它不注册HTTP地址，不创建会话，也不发送问题。

## 预期流程

```text
将来由已认证的聊天入口传入user_id
  → 校验user_id为正整数
  → await凭据业务.get_api_key(user_id)
      → 仓储读取该用户的密文
      → 加密器验证并解密
      → 返回原始Key，仅供后端内部使用
  → await to_thread(网关构造器, api_key=本人的Key)
  → 返回新ModelGateway对象
  → 将来由聊天业务调用它，并管理模型客户端的生命周期
```

每次创建都重新读取当前用户的Key，这样修改或删除个人配置后，后续创建不会继续使用旧缓存。一个已经在执行的请求不会因为删除配置而自动取消，取消属于另外的运行控制。

这个工厂不把user_id、api_key或创建出的网关写到self上，也不把带用户Key的网关放进lru_cache。`self.credential_service` 和 `self.gateway_factory` 是可复用的协作者；每次方法调用中的user_id、api_key、gateway是本次局部变量。

## 4个TODO如何填写

### TODO 1：校验用户ID

已有工具 `validate_positive_integer` 接收“值”和“字段名称”，返回合法整数，否则抛ValueError。字段名称使用“用户 ID”，返回值仍赋给user_id。不要使用int(user_id)把用户传入的任意内容强行转成身份。

本工厂的用户ID将来来自Token校验结果；正整数检查只检查数据格式，不代替登录验证。

### TODO 2：取得本人的原始Key

调用 `self.credential_service.get_api_key(user_id)`，因为它是async方法，需要await。用局部变量api_key接收。

这里调用get_api_key，而不是is_configured：后者只告诉你是否存在记录，不能取得创建模型客户端所需的Key。不要在工厂中重新写SQL或自己解密，已有业务已经提供了完整能力。

未配置会抛ModelCredentialNotConfiguredError；解密失败会抛ModelCredentialDecryptionError；数据库故障继续抛MySQL驱动异常。本层不吞掉它们，也不换成其他用户或平台共享Key。将来HTTP层会按异常类别给出安全响应。

### TODO 3：创建ModelGateway

使用 `await asyncio.to_thread(...)`，用gateway接收结果。第一个参数是 `self.gateway_factory` 这个可调用对象，其余通过 `api_key=api_key` 传入。

注意区别：把函数或类本身交给to_thread，线程才能执行它；如果你先写括号调用，就会先在事件循环线程里执行构造函数。

构造函数默认把 `ModelGateway` 类放在self.gateway_factory中。调用这个类相当于创建一个ModelGateway实例；检查脚本会传入假构造器，完全不会创建真实模型客户端。

### TODO 4：返回新对象

返回gateway本身，随后删除占位NotImplementedError。不要返回Key字符串，不要调用invoke，不要打印Key。

创建网关和向模型发送消息是两个动作。这个练习只完成创建；后续接入聊天时会统一处理调用、请求结束后的HTTP客户端资源释放、超时和失败状态，再做接口验收。

## 导入的包和对象

| 来源 | 对象 | 在这里的作用 |
| --- | --- | --- |
| Python标准库asyncio | to_thread | 将同步网关构造放到线程执行；它返回可等待对象，要await取得构造结果 |
| Python标准库collections.abc | Callable | 类型标注，表示gateway_factory是一个可以调用并返回ModelGateway的对象；不负责运行它 |
| 项目日志模块 | logged_operation | 给构造与创建操作补日志，记录结果与错误位置 |
| 项目凭据业务模块 | ModelCredentialService | 提供async get_api_key，避免工厂重复实现SQL和解密 |
| 项目模型调用模块 | ModelGateway | 默认网关构造器，以及方法返回值的类型标注 |
| 项目校验模块 | validate_positive_integer | 拒绝0、负数、布尔值、字符串等不符合要求的用户ID |

ModelGateway内部使用第三方langchain_deepseek.ChatDeepSeek完成SDK调用；这个细节由原有网关封装，本工厂不直接操作SDK。没有新增第三方依赖。

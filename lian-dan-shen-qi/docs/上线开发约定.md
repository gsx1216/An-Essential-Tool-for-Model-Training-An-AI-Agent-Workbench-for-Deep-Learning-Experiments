# 上线开发约定

这些是用户明确提出的后续开发约束。

- 目标为多用户上线。按阶段开发，但不能把手动输入 user_id 当成身份认证，也不能把未完成的认证功能称为已经可以上线。
- 业务逻辑尽量由用户手写；助手提供骨架、检查和解释。SQL、安全基础实现、测试由助手协助完成；用户明确要求直接修改时可直接实现该部分。
- 用户已明确要求个人模型 Key 的加解密工具由助手完整实现，并修正本次已写错的代码；后续普通业务继续采用骨架与用户手写、助手检查的方式。
- 每次代码检查必须明确指出实际错误所在的文件、函数和行号，说明错误原因、触发条件及会造成的结果；区分功能错误、未完成项和可选改进，没有发现错误时如实说明，不为讲解而编造问题。
- 指出错误时同时给出具体修改方案、理由和必要的修改示例，让用户可以自己修改；除用户明确要求直接修改，或双方已约定由助手负责的部分外，不替用户补完核心业务。
- 每次检查同时讲解本次功能的完整执行逻辑：从入口开始，按调用顺序解释输入、校验、异步调用、数据库操作、返回值，以及成功和异常分支；说明对象与数据从哪里来、交给谁、最终得到什么。
- 用户于2026-10-24补充：讲解要结合每个参数与依赖逐层展开。例如说明Depends如何调用require_current_user、后者又依赖谁、谁只提取Token、谁查询数据库验证Token、返回对象有哪些字段，再沿实际调用顺序解释后续模型请求；不能只列抽象模块名。
- 每次检查逐一说明本次涉及的各模块和文件的职责、相互调用关系，以及各函数和类在流程中的作用；结合当前代码讲解，避免只给抽象名词。
- 每次检查解释本次相关代码中引用的包、模块和导入对象，区分 Python 标准库、第三方依赖和项目自己的模块；说明为什么导入、具体使用了什么函数或类、在当前流程中解决什么问题，包含有关的装饰器、异常类和校验工具。
- 检查反馈给出已执行的验证结果和必要的测试用例，明确哪些是模拟测试、哪些连接了真实依赖、哪些仍未验证；先讲清本次问题与逻辑，再安排下一步任务。

- 模型采用用户自带 API Key。正式调用必须取当前登录用户自己的 Key；没有配置就拒绝调用，不能回退到平台共享 Key。
- 用户模型 Key 通过已鉴权接口提交，加密保存到 MySQL；加密主密钥与数据库密文分开管理。不得通过普通用户接口修改全局 .env。
- MySQL 连接密码属于部署配置，不属于普通用户的输入。登录密码只保存慢哈希；模型 API Key 需要可逆加密，两者不可混用。
- 不主动调用真实收费模型、购买收费服务、充值或开通付费资源。测试使用模拟模型；真实数据库验证仅使用已有本机 MySQL 和独立临时测试库。
- 现有测试数据保留。用户说以后会清空不等于现在执行清空；迁移不得为了省事重置密码、删除会话或改变归属。
- 支持用户显式删除自己选定的一整段聊天；必须校验当前登录身份与会话归属，并在同一事务中删除会话、消息和轮次。不能只在前端隐藏标题；删除后旧生成任务不能重新写回内容，也不能影响其他会话、账号或登录凭证。
- 历史展示和模型上下文读取分开：点击会话时只读取分页消息用于展示，不自动调用模型；发送问题或重试时，按已认证身份和会话重新读取服务端上下文，不能直接把浏览器分页历史作为可信的完整模型输入。
- 上线前还需完成登录态、权限隔离、登录限流、HTTPS、个人模型凭据管理和聊天接口。这些不能被当前的单元测试结果代替。
- 每完成一部分就检查一部分：先验证正常和异常情况，再联调真实本机依赖，通过后继续。报告中明确区分模拟测试与真实数据库联调；真实写入测试使用独立临时库，不能把单元测试通过当作真实链路已经通过。
- 注册密码按用户要求设置为 8～32 个字符，不自动截断或去除空格；保留对旧账号已存长密码哈希的登录验证兼容。
- 注册、登录接口和登录态阶段完成后，生成 docs/注册登录完整流程说明.md，并给相关 Python 文件补充职责与关键校验注释。文档按调用顺序解释各文件主次职责、校验位置、异常处理以及成功和失败实例。
- 注册、登录接口遇到数据库异常时，对用户统一返回 HTTP 503 和“请稍后重试。”，不在响应中说明是数据库问题，也不暴露连接信息。
- 登录 Token 默认有效期按用户要求设为 3 天（259200 秒），当前允许配置范围为 1～259200 秒；这是签发后的固定有效期，后续由服务端保存并校验。
- 日志必须持久化，不能只依赖控制台异常。接口和已实现的业务、仓储操作统一记录；同一请求内相同异常去重。记录请求编号、操作、结果、耗时及安全堆栈，不记录密码、API Key、原始 Token、请求正文、SQL 参数、返回正文和局部变量。用户仍只收到通用错误提示。
- 日志默认参照用户桌面“实习项目/马来西亚舆情预警系统”中 about_log.py 的可读布局，显示时间、级别、模块、函数、行号、线程、请求编号、结果和原因分类，帮助定位具体失败位置；保留敏感信息保护。

- 用户于 2026-10-25 补充：每次完成修改，最终回复必须分别列出“新增文件”和“修改文件”，逐项给出真实文件名/路径及简短用途，文档、SQL、测试和脚本也计入；不能只说明功能或只列目录、通配符。文件较多时同时生成完整 Markdown 变更清单，明确阶段范围和文件数量，不把本阶段未改的文件列入。若有删除/重命名或数据库表、索引迁移，另行说明。保留本次验证结果与尚未接通的功能说明。

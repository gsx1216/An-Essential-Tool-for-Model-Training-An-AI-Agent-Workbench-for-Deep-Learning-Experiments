## ReAct 式提示词流程

用户确认采用“核对现有代码和日志后给建议”的 ReAct 分析流程。本次在普通文本建议的系统提示词中增加：检查代码形成检查点 → 回到原始代码与日志核对 → 根据证据更新判断 → 给出修改和验证方法。

重点围绕当前主网络文件中实际出现的数据流、forward、张量形状、分支融合、上下采样、归一化和重复计算。区分代码可确认问题与待验证假设；未读取的依赖和没有执行的实验不得当作已知结果。

最终仅显示“问题（已确认/待验证）→代码及日志依据→修改建议→验证方法”。不展示内部思考、Thought/Action/Observation 标记或工具协议。本次是提示词中的证据检查流程，仍然只有一次普通模型请求，没有重新引入模型工具循环。

## 日志位置和格式

默认位置：E:/code/LangChian_New/logs/YYYY-MM-DD/app.txt。

按服务器本机日期每天一个 UTF-8 TXT，API、监控及其他业务 Worker 共用，不再按进程号或文件大小拆分。Windows 使用 msvcrt 文件锁，其他平台使用 fcntl 文件锁，整条多行异常在同一个跨进程锁内追加。每天自动切换日期目录，沿用原有 7 天日目录保留规则。

每条记录包含：本机时间及 UTC 偏移、级别、模块/函数/代码行、进程号、线程、追踪号、操作名及耗时；失败另含固定可读原因和调用栈。独立 Worker 的 __main__ 日志、Uvicorn 服务错误及第三方告警/异常也进入该文件；HTTP 请求使用原有中间件日志，避免原始查询字符串泄漏。

模型请求返回时增加安全诊断字段：

| 字段 | 含义 |
| --- | --- |
| content_kind | text / blocks / other |
| content_chars / content_bytes | 正文字符数与 UTF-8 字节数 |
| content_blank | 是否没有有效正文 |
| finish_reason | stop / length / tool_calls / content_filter / unknown |
| output_tokens / reasoning_tokens | SDK 提供时的输出与思考额度 |
| reasoning_chars | 思考内容长度，仅记录数字 |
| reply_code | 本次具体失败分类 |
| network_lines / log_bytes_sent / log_clipped | 建议输入范围 |

不记录 Key、密码、模型正文、思考正文、完整提示词、私有源码或请求体。原有脱敏和异常去重继续生效。APP_LOG_FORMAT=json 仍可供结构化日志的部署及测试使用，文件仍为每日 app.txt；默认是可读文本。

已将 7 个日期目录的 119 个旧分进程文件按时间汇总到各日 app.txt。原文件移至 logs/legacy/YYYY-MM-DD/ 备份，不在新业务日志中继续写入。旧记录保留原来的 UTC 时间，新记录使用本机时区。

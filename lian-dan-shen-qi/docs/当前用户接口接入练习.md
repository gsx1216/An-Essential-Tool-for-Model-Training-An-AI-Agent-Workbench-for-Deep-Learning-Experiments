# 当前用户接口接入练习

目标：登录取得 access_token 后，携带 `Authorization: Bearer <access_token>` 请求 `GET /auth/me`，得到这个 Token 所属用户的信息。不要让客户端输入 user_id 来指定身份。

当前状态：本练习已经完成并通过单元与真实临时 MySQL 接口联调，下文保留实现步骤供回顾。完整说明见 `docs/注册登录完整流程说明.md`，接下来填写退出登录业务。

本练习包括对象组装、请求头提取、业务调用和接口返回。异常到 HTTP 状态码的转换、日志以及 HTTPBearer 对象属于基础设施。

## 第一步：组装业务对象

填写 `app/api/dependencies.py` 最下面的 `get_current_user_service()`，共四个 TODO：读取后端数据库密码、创建仓储、创建 Token 工具、返回 `CurrentUserService`。

可以参考同文件的 `get_login_service()`。这个工厂使用 `@lru_cache(maxsize=1)` 复用服务对象，不缓存每个用户的校验结果。不要把本次请求的 Token 放到工厂或对象属性里。

## 第二步：完成 HTTP 鉴权依赖

填写新文件 `app/api/auth_dependencies.py` 中的四个 TODO。

`get_bearer_token()` 只处理请求头：凭证缺失时返回 401，存在时取出原始 Token 字符串。`HTTPBearer(auto_error=False)` 是 FastAPI 提供的请求头解析工具；它不负责检查数据库记录、有效期或撤销状态。

请求头和解析结果的关系：

```text
Authorization: Bearer abc...
    credentials.scheme       → "Bearer"
    credentials.credentials  → "abc..."
```

`require_current_user()` 负责 await 调用已经完成的 `CurrentUserService.get_current_user()`，并把得到的 `(user_id, username)` 转成 `UserResponse`。401 和 503 的异常处理已经提供，不要额外捕获所有 ValueError，否则可能把内部程序错误误报成凭证无效。

提取 Token 的依赖写在服务工厂依赖之前，缺少凭证时可以先拒绝请求。只有服务工厂可以缓存，`require_current_user()` 和 `get_bearer_token()` 不加 lru_cache；每次请求都必须重新检查登录记录。

## 请求的执行顺序

```text
GET /auth/me
  → FastAPI 找到注册的 read_current_user
  → HTTPBearer 解析 Authorization
  → get_bearer_token 取出 Token，缺失则 401
  → get_current_user_service 提供业务服务
  → require_current_user 调用业务层
      → 计算哈希、查询有效登录记录
      → 无效则 401；数据库故障则 503
      → 成功后返回 UserResponse
  → read_current_user 返回 current_user
```

接口处理函数不需要再次核对密码或用户是否存在。依赖失败时会抛出 HTTPException，处理函数不会继续执行。

| 场景 | 应有结果 |
|---|---|
| 未携带凭证，或认证方式不是 Bearer | 401，并包含 WWW-Authenticate: Bearer |
| Token 格式错误、未知、到期或已撤销 | 401，统一提示重新登录 |
| 有效 Token | 200，返回 user_id 和 username |
| 不同用户的 Token | 返回各自用户，不能串号 |
| 数据库故障 | 503，响应只提示“请稍后重试。” |
| 内部意外错误 | 500，响应只提示“请稍后重试。” |
| 重复查询当前用户 | 不创建登录记录，不延长 Token 到期时间 |

目前还没有退出登录接口，撤销和到期场景用独立临时库构造验证，不清空或修改现有业务数据。

# 注册登录完整流程说明

本文对应已经完成的注册、登录签发凭证、`GET /auth/me` 身份校验和 `POST /auth/logout` 退出登录。四个接口已通过回归测试及真实本机 MySQL 独立临时库联调。

## 一、先看主次关系

```text
app/main.py：创建应用，注册路由、请求日志和异常处理
  → app/api/auth_routes.py：接收 HTTP 请求，调用业务或身份依赖
      → app/api/dependencies.py：提供可复用的服务对象
      → app/services/*.py：决定业务执行顺序
          → app/security/*.py：密码与凭证计算
          → app/repositories/*.py：参数校验、执行 SQL、处理事务
              → app/database.py：建立 MySQL 连接
              → sql/*.sql：参数化数据库语句
```

`/auth/me` 还有身份依赖层：`app/api/auth_dependencies.py` 先提取请求头中的 Token，再调用业务校验。依赖失败会抛出异常，接口处理函数不会继续执行。

路由负责 HTTP 输入输出；业务服务负责流程；仓储负责持久化；安全工具负责哈希和随机凭证。服务对象创建成功不表示用户登录成功。

## 二、各文件负责什么

| 文件 | 主职责与校验位置 |
|---|---|
| `app/main.py` | 创建 FastAPI 应用，include_router 注册接口，启用统一日志与请求校验异常处理 |
| `app/api/schemas.py` | 声明请求字段类型和响应字段；缺字段、错误类型等由 FastAPI/Pydantic 返回 422 |
| `app/api/auth_routes.py` | 注册、登录、当前用户和退出 HTTP 入口；转换已知异常，返回公开字段或空的 204 |
| `app/api/dependencies.py` | 读取部署配置，组装 AuthService、LoginService、CurrentUserService、LogoutService；按进程缓存协作者 |
| `app/api/auth_dependencies.py` | 提取 Bearer Token，await 身份校验，把无效凭证转换为 401，把数据库故障转换为 503 |
| `app/services/auth_service.py` | 注册时规范用户名并生成密码哈希；登录时核对已有账号密码 |
| `app/services/login_service.py` | 账号密码验证成功后，生成 Token、哈希和有效期，保存成功后才返回凭证 |
| `app/services/current_user_service.py` | 检查 Token 格式，计算哈希，查询仍有效的登录记录，返回数据库确认的用户 |
| `app/services/logout_service.py` | 校验当前 Token，通过工作线程执行原子撤销；无匹配有效记录时抛出业务异常 |
| `app/security/passwords.py` | Argon2id 密码哈希与核对；注册 8～32 字符，兼容旧账号已存的更长密码哈希 |
| `app/security/tokens.py` | 生成安全随机 Token、SHA-256 哈希、UTC 到期时间；不自行确认身份 |
| `app/models/login_result.py` | 装载登录业务结果，路由再转换为 LoginResponse；不负责认证 |
| `app/repositories/user_repository.py` | 参数化查询账号、校验待存密码哈希、保存账号并处理用户名唯一约束 |
| `app/repositories/login_session_repository.py` | 保存登录记录；查询未过期、未撤销的凭证身份；原子撤销单个凭证 |
| `app/database.py` | 按部署配置建立连接，提供受控的建表与迁移命令；不在普通请求里自动清空数据 |
| `app/config.py` | 读取后端部署配置，本地可读取 config/.env；普通用户不提供 MySQL 管理密码 |
| `app/validators.py` | 共用的文本、正整数、会话 ID 等输入校验；具体入口按业务需要调用 |
| `app/errors.py` | 提供可区分的业务异常，业务层无需依赖 HTTPException |
| `app/api/error_handlers.py` | 返回安全的 422 错误结构，不回显密码等原始请求内容 |
| `app/api/request_logging.py` | 为请求生成 X-Request-ID，记录状态与耗时，将未处理异常转换为通用 500 |
| `app/logging_config.py` | 日志格式、源码定位、异常去重、落盘与轮转；不记录参数、凭证或局部变量 |

## 三、注册是如何执行的

请求：`POST /auth/register`，JSON 包含 username 和 password。

1. `RegisterRequest` 解析输入。password 的 `SecretStr` 负责遮蔽对象展示，尚未生成密码哈希。
2. 路由调用 `get_secret_value()` 取出输入的原始字符串。这是读取值，不是解密。
3. `AuthService.register()` 规范用户名，要求非空且最多 64 字符。
4. 通过 `await asyncio.to_thread(...)` 调用 PasswordService，检查新密码为 8～32 字符并生成 Argon2id 哈希。不去除密码空格，不截断。
5. 通过工作线程调用 UserRepository，使用参数化 SQL 插入账号和密码哈希。
6. MySQL 用户名唯一约束负责处理并发重复注册。冲突转换为 UsernameAlreadyExistsError；成功提交后返回数据库生成的用户 ID。
7. 路由返回 201 和 UserResponse，只包含 user_id、username。注册本身不签发 Token。

SQL 文件：`sql/create_registered_user.sql`。密码哈希在入库前还会检查其编码格式，防止误把明文写到 hash 字段。

## 四、登录是如何执行的

请求：`POST /auth/login`，JSON 包含 username 和 password。

```text
LoginRequest
  → 路由取出原始密码
  → LoginService.login()
      → AuthService.authenticate()
          → 按用户名查询 users
          → PasswordService.verify_password() 核对 Argon2id 哈希
          → 返回数据库中的用户 ID 和用户名
      → 创建安全随机 Token
      → 计算 Token 哈希与到期时间
      → 保存 login_sessions 并提交事务
      → 返回 LoginResult
  → 路由组织 LoginResponse，HTTP 200
```

用户不存在、没有设置密码或密码错误，都使用统一的账号密码错误提示。缺失账号会使用 dummy 验证流程，不会因为用户传入某个特殊密码就通过验证。

登录时使用密码验证函数，不能重新生成一个随机盐哈希后直接和数据库字符串比较。

只有账号密码核对阶段的拒绝会包装为 InvalidCredentialsError。后面的凭证计算、插入或提交故障不冒充密码错误。

Token 使用 32 个安全随机字节，编码后为 43 个 URL 安全字符；默认有效期为 259200 秒，即 3 天。原始 Token 返回给客户端，数据库保存 64 位小写十六进制 SHA-256 哈希。Token 有足够随机性，身份仍需查数据库确认，不能只看它的格式。

SQL 文件：`sql/get_user_auth.sql`、`sql/save_login_session.sql`。响应含凭证，设置 Cache-Control: no-store 和 Pragma: no-cache。

## 五、后续请求如何确认当前用户

请求：`GET /auth/me`，请求头携带 `Authorization: Bearer <access_token>`。

1. FastAPI 匹配注册在 router 上的 `/me`，加上 router 的 `/auth` 前缀，得到 `/auth/me`。
2. `Depends(require_current_user)` 要求先执行身份依赖。
3. HTTPBearer 解析请求头。缺失或不是 Bearer 时，提取依赖返回统一 401，并带 WWW-Authenticate: Bearer。
4. `get_bearer_token()` 返回原始 Token 字符串，不包含前面的 `Bearer `。
5. `get_current_user_service()` 提供服务对象，不直接决定用户是谁。
6. `require_current_user()` 使用 await 调用异步业务方法，得到 `(user_id, username)`。
7. 业务方法先确认字符串类型和 43 位允许字符，再计算哈希，通过工作线程查询仓储。
8. SQL 同时要求哈希匹配、revoked_at IS NULL、expires_at 大于当前 UTC 时间，并关联 users。
9. 查不到结果统一拒绝；查到后组织 UserResponse，交给接口返回。不会重新签发 Token，也不会延长三天有效期。

SQL 文件：`sql/get_active_login_user.sql`。客户端传入 user_id 或 username 查询参数不能改变认证身份，用户信息只取自 Token 对应的数据库记录。

HTTPBearer 负责提取凭证，数据库查询负责确认它仍有效。只生成一个看起来符合格式的随机字符串不能登录。

### 退出当前登录

请求 `POST /auth/logout`，携带当前 Token。get_bearer_token 提取凭证，get_logout_service 提供服务对象；路由 await 调用 LogoutService.logout。

服务检查格式并计算哈希，通过工作线程调用仓储。`sql/revoke_login_session.sql` 用一条 UPDATE 同时检查哈希、未撤销和未到期，并设置 revoked_at。事务提交后仓储返回 True；没有匹配的有效记录则返回 False。

服务收到 True 后正常返回 None，表示操作完成且没有返回数据；收到 False 则抛出 InvalidTokenError。路由成功返回空的 204，并设置不缓存响应头；异常分别转换为 401 或通用 503。不能把服务成功返回的 None 当成失败。

退出只撤销请求中这一条凭证，不删除用户、聊天记录或其他登录。同账号另一 Token 及其他用户仍可使用。再次使用已撤销 Token 请求 /auth/me 或 /auth/logout 均为 401。

## 六、两个认证表保存什么

| 表 | 关键内容 |
|---|---|
| `users` | 用户 ID、唯一用户名、Argon2id 密码哈希、创建时间 |
| `login_sessions` | 登录记录内部 ID、所属用户 ID、唯一 Token 哈希、创建时间、到期时间、撤销时间 |

login_sessions 的内部自增 ID 不是登录凭证。每次登录可以生成一条新记录，因此同一用户可以同时有多个不同 Token。

`chat_sessions` 和 `chat_messages` 属于聊天数据，与登录记录不同。以后聊天接口应使用身份依赖给出的 user_id 做归属校验。

## 七、self、缓存、Depends 怎样配合

- `self.session_repository`、`self.token_service` 保存当前服务对象的协作者。
- `@lru_cache(maxsize=1)` 缓存无参数工厂的返回值，以复用服务对象，不缓存每次请求的身份结果。
- `Depends(...)` 让 FastAPI 执行依赖并把返回值传给参数，失败时终止接口处理。

每次请求的 Token、哈希、user_id、username 使用局部变量，不保存成共享服务的“当前用户”属性。多个请求可以复用协作者，但不能互相覆盖身份。

每个 Python 进程有自己的对象缓存。多个进程或 Pod 必须连接同一份持久化登录数据，才能共享登录状态。当前仓储每次操作创建并关闭自己的数据库连接；缓存服务对象不等于缓存一个数据库连接。

## 八、async、await 与事务的位置

| 调用 | 写法 |
|---|---|
| LoginService、CurrentUserService、LogoutService 的异步方法 | await 调用 |
| 同步 MySQL 仓储、Argon2 密码计算 | await asyncio.to_thread(函数本身, 参数...) |
| Token 哈希、随机生成与时间计算 | 普通同步调用 |

异步方法直接调用得到协程对象，不能直接拆成 user_id、username。必须 await 等待结果。to_thread 的第一个参数传函数本身，不先加括号执行。

写数据库由仓储明确 commit；失败时 rollback 后继续 raise。日志不会替代事务提交，也不能吞掉错误后返回成功。

## 九、失败怎样返回给客户端

| 情况 | HTTP 状态与处理 |
|---|---|
| 缺字段、字段类型错误、JSON 无法解析 | 422，安全的输入校验信息 |
| 注册用户名或密码不符合业务要求 | 400，固定提示 |
| 用户名已注册 | 409，用户名已存在 |
| 登录账号密码不匹配 | 401，统一账号密码错误 |
| Token 缺失、错误、未知、到期或已撤销 | 401，统一重新登录提示与 Bearer challenge |
| MySQL 查询、写入或提交故障 | 503，只返回“请稍后重试。” |
| 意外程序错误 | 500，只返回“请稍后重试。” |

后台日志通过 X-Request-ID 关联。日志显示文件、函数、行号、异常类型、MySQL 错误编号与安全调用栈；不输出原始异常文本、密码、Token、哈希、请求正文或局部变量。

## 十、如何在 docs 验证

1. 启动 `python -m uvicorn app.main:app --reload`，打开 `/docs`。
2. 调用 `/auth/register` 创建账号；再调用 `/auth/login`。
3. 从实际 Server response 的 Response body 复制 access_token，示例 Example Value 不能证明调用成功。
4. 点击 Authorize，只输入 Token 本身，不加 Bearer 前缀。
5. 执行 GET /auth/me，应返回刚才登录的用户。Authorize 负责让 Swagger 发送请求头，本身不保证 Token 有效。
6. 保留授权输入，执行 POST /auth/logout，应返回 204 且没有响应正文。
7. 保留同一 Token，再请求 /auth/me 或 /auth/logout，应为 401。
8. Swagger 授权弹窗的 Logout 只清除浏览器文档的凭证输入，不会撤销服务器的登录记录；服务器撤销由 POST /auth/logout 完成。

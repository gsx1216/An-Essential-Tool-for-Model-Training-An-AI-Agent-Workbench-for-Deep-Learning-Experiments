## 推荐：各类任务统一输出 JSONL

JSONL 指每条 JSON 独占一行。普通说明、警告可以继续打印；需要绘图的数值单独输出一行：

```json
{"type":"metric","step":1,"epoch":1,"dataset":"my_dataset","split":"train","loss":0.5,"learning_rate":0.0001}
```

| 字段 | 约定 |
| --- | --- |
| type | 固定为 metric |
| step | 必填，全局训练步数的非负整数；不要每个 epoch 重新从 0 开始 |
| epoch | 可选，非负整数 |
| dataset | 可选，数据集标识；省略为 unspecified。使用小写字母、数字、下划线、点或连字符 |
| split | train、validation 或 test；省略为 train |
| 其他字段 | 实际数值指标，如 loss、accuracy、iou、map、mae、s_measure。名称用小写字母开头，后续为小写字母、数字或下划线；一次最多 16 个 |

数值不能是字符串、null、NaN 或 Infinity。指标名称不限定研究方向，不要求同时包含 loss 和 accuracy，也不由系统推测指标含义。

PyTorch 训练循环中可使用现有变量输出，例如：

```python
import json

# global_step 由训练循环维护，跨 epoch 递增。
record = {
    "type": "metric",
    "step": global_step,
    "epoch": epoch,
    "dataset": "my_dataset",
    "split": "train",
    "loss": float(loss.item()),
    "learning_rate": float(optimizer.param_groups[0]["lr"]),
}
print(json.dumps(record, allow_nan=False), flush=True)
```

这段是接入示例，需要放到自己的脚本并使用实际变量。flush=True 让日志及时写出；只在 TensorBoard 或其他文件里记录、没有写入本次运行采集的标准输出日志，也不会自动被本系统识别。运行中进程不会因为修改磁盘上的 Python 文件自动执行新增的 print。

## 兼容：普通文本可自行配置规则

运行详情 → 概览 → **日志格式与采集规则**，可以查看上述协议。没有任何有效指标时，还可以为这次运行保存普通文本规则，例如匹配：

```text
step=1 loss=0.5
step=2 loss=0.25
```

对应配置：

```json
{
  "rules": [
    {
      "pattern": "step=(?P<step>\\d+)\\s+loss=(?P<loss>[-+0-9.eE]+)",
      "dataset": "my_dataset",
      "split": "train",
      "metrics": ["loss"]
    }
  ]
}
```

页面“填入普通文本解析示例”只演示这一种通用写法，用户必须对照自己的真实日志调整，不会自动套用到其他格式。最多 8 条规则，每条需要 step 或 epoch 命名组，并让 metrics 中的名称对应数值命名组。同一原始行使用第一条匹配规则；未匹配的行继续计入 ignored。原生 JSONL 优先，已有规范输出时无需额外规则。

保存成功会把这个**零有效指标运行**的采集游标重置到开头，然后补采一批历史日志；未读完时可继续手动采集，后台 Worker 也会继续推进。不改训练进程、不修改远端日志、不改变启动快照。返回每个事件的 source_offset 仍是原始日志的字节位置，支持查证和去重。

如果已有有效指标，不能改成另一套规则覆盖数据，接口返回 409；重复提交相同规则可成功且不会清空数据。配置和游标重置在同一短事务中完成，同时增加 revision，让使用旧版本的在途采集无法写回旧结果。

## 页面反馈

- 提取到新事件：显示“已采集 N 条新指标”。
- 日志已读、有忽略行且有效指标为 0：提示核对日志格式或配置规则。
- 已有指标但没有新记录：显示“暂时没有新增指标”。
- 解析规则保存后仍不匹配：保留“本批日志仍没有匹配到指标”的提示。

不再仅因读取接口成功，就提示已采集到指标。

## 接口

| 方法和路径 | 行为 |
| --- | --- |
| GET /runs/{run_id}/metrics/parser | 读取本人运行的规则，默认 rules=[]；不连接 SSH |
| PUT /runs/{run_id}/metrics/parser | 请求体为上面的 rules 对象；仅零有效指标时修改规则并重置游标；不启动训练 |
| POST /runs/{run_id}/metrics/sync | 原有采集接口，新增 new_events 字段，stream 继续返回 valid、ignored、caught_up 等状态 |

所有接口使用当前用户的登录 Token。规则接口不存在/越权为 404，未登录为 401，参数不符合为 422；已有指标冲突为 409。规则接口不接受用户上传指标数值，数值仍须来自服务器原始日志。
